# 威胁模型连续化重构（离散五档 → 连续 sigmoid）

> 状态：**工作区未提交、未单独上真机**（仅 sim A/B 验证 +2.93）。
> 涉及文件：`src/strategy.cpp`、`include/simuro5/defense.hpp`、`include/simuro5/situation.hpp`、`src/situation.cpp`、`src/defense.cpp`、`src/roles.cpp`（后两处为阈值改名 + 门将前出修复混在同一文件，需拆分提交）。
> 日期：2026-09-21。

---

## 0. 一句话结论

把 `threat_from_state` 从「按球位 + 球速升档」的**离散五档 if/else**，换成「位置 + 速度 + 角度」三项相加的**连续 sigmoid**。下游分支不再读魔法数字 0.3/0.6，改读 `retreat_threat()` / `mark_engage_threat()` 两个命名阈值（返回值不变，仍是 0.30 / 0.60）。

**核心动机是修真机「漏防快攻」；但目前只在 sim 验证过，没在真机坐实。**

## 1. 原模型（离散五档）

`src/strategy.cpp::threat_from_state` 旧实现：

```cpp
double Strategy::threat_from_state(const WorldModel &wm) const {
    if (wm.team_state == TS_ATTACK) return 0.1;          // 我方控球：低威胁
    if (in_penalty_area(ctx, wm.ball.x, wm.ball.y)) return 1.0;   // 球在己方罚球区
    bool our_half = ctx.attack_dir() > 0 ? (wm.ball.x < 110.0) : (wm.ball.x > 110.0);
    double threat = our_half ? 0.6 : 0.4;                // 己方半场 0.6 / 对方半场 0.4
    const double kThreatDangerSpeed = 6.0;               // cm/帧：朝门有效速度阈值
    if (ball_danger_speed(wm) > kThreatDangerSpeed) {    // 球速朝门 → 升档
        threat = our_half ? 0.8 : 0.6;
    }
    return threat;
}
```

档位表：

| 条件 | 威胁值 | 触发 |
|---|---|---|
| 我方控球（TS_ATTACK） | 0.1 | 无防守动作 |
| 球在己方罚球区 | 1.0 | 全员回缩 |
| 球在己方半场 | 0.6 | 人盯人（≥0.6） |
| 球在对方半场 | 0.4 | 仅回防（>0.3） |
| 球速朝门 >6 cm/帧 | 己方半场 0.8 / 对方半场 0.6 | 提前升档 |

**下游阈值**（当时硬编码在 `run_passive`/`run_assist`/`run_midfield`/`double_team_point`/`update_stand_points`）：
- `> 0.3` → assist / midfield 回防
- `>= 0.6` → passive 人盯人、double_team、站位回收

另外 `Situation::analyze` 里还有一段**死代码**：`sit.threat_level` 按 0.1/0.3/0.6/1.0 赋值，但从未被读走（`Strategy::run` 只复制了 `sit.we_have_ball`），真正生效的是 `update_team_state → threat_from_state` 写进 `wm.threat_level`。本次一并删除。

## 2. 新模型（连续 sigmoid）

```cpp
TUNABLE(kThreatAttack,     0.10);   // 进攻态固定威胁（不变）
TUNABLE(kThreatD0,       120.0);    // 位置 sigmoid 中点：距门此距离威胁=0.5（cm）
TUNABLE(kThreatK,         32.0);    // 位置 sigmoid 陡度（越小越陡）
TUNABLE(kThreatSpeedGain,  0.50);   // 满速加成上限（原 0.22 → 提到 0.5）
TUNABLE(kThreatSpeedRef,   6.0);    // 球速此值(cm/帧)=满加成（原 10 → 改回 6）
TUNABLE(kThreatAngleGain,  0.12);   // 中路(贴门心 y=90)加成上限

double Strategy::threat_from_state(const WorldModel &wm) const {
    if (wm.team_state == TS_ATTACK) return kThreatAttack;   // 0.10，精确保持（offline_test 依赖）

    double d      = ctx.dist_our_goal(wm.ball.x);   // 0=己方门线，220=对方门线
    double danger = ball_danger_speed(wm);          // 球朝己门速度分量 cm/帧

    double pos = 1.0 / (1.0 + std::exp((d - kThreatD0) / kThreatK));  // 位置项
    double spd = kThreatSpeedGain * clamp(danger / kThreatSpeedRef, 0.0, 1.0); // 速度项
    double ang = kThreatAngleGain * (1.0 - std::fabs(wm.ball.y - 90.0) / 90.0); // 角度项

    return clamp(pos + spd + ang, 0.0, 1.0);
}
```

三项分解：

| 项 | 公式 | 范围 | 语义 |
|---|---|---|---|
| **位置** `pos` | `1/(1+exp((d-120)/32))` | 0~1 | 球离己门越近越危险，sigmoid 平滑 |
| **速度** `spd` | `0.5 · clamp(danger/6, 0, 1)` | 0~0.5 | 球朝门速度连续加成（快攻/远射提前） |
| **角度** `ang` | `0.12 · (1-|y-90|/90)` | 0~0.12 | 球越居中越危险，贴边 y=0/180 无加成 |

标定参考（位置项单看）：`d=120`(中线)≈0.5、`d=85`(罚球区)≈0.75、`d=40`(门区)≈0.92。

**下游阈值语义不变**（改名，返回值不变）：

```cpp
// include/simuro5/defense.hpp
inline double retreat_threat()     { return 0.30; }  // >它 → assist/mid 回防
inline double mark_engage_threat() { return 0.60; }  // >=它 → 人盯人/double_team/站位回收
```

## 3. 为什么改（原因，逐条）

### 原因 1：原五档跳变突兀，阈值附近每帧横跳
原模型在「罚球区边界」威胁从 0.6 **直接跳到 1.0**、在「中线」从 0.4 硬切到 0.6。球贴着阈值线来回时，下游分支（回防/盯人/回缩）跟着每帧切换，是**角色与阵型抖动**的来源之一。sigmoid 让威胁随距离平滑过渡，消除边界跳变。

### 原因 2：球速只有「二元升档」，表达不了连续危险度 —— 真机漏防快攻
原模型 `danger > 6` 才升一档（0.6→0.8 / 0.4→0.6）。球速 6.1 与 30 cm/帧在威胁值上**等价**，快攻/远射的「越快越危险」被抹平。真机复盘发现**漏防快攻**（demo 高速推进时全队没提前回防），这是本次改动的直接触发点。

### 原因 3：原模型不含「角度/中路」因子
球在边路贴边推进与中路推进同档，中路威胁被低估、边路被高估。角度项 `ang` 让中路（y=90）危险度略高、贴边（y=0/180）无加成。

### 原因 4：连续化后系数全 TUNABLE，可交 sim A/B 搜索
旧模型档位是写死的 if/else，没法搜。新模型 6 个 `TUNABLE` 系数可进既定调参流水线（`sim_bench` A/B + 种子集）。

> ⚠️ **不成立的理由（诚实说明）**：sim A/B 的 +2.93 是「调得更激进（更早回防）」的收益，不是「连续化」本身带来的收益。同样的激进程度，在旧模型上把 `kThreatDangerSpeed` 从 6 调低、或把 `retreat_threat` 从 0.3 调低也能拿到。连续化的边际价值是**可调性 + 平滑**，不是新增了旧模型做不到的能力。
