# 19 · 陪练（黄队）修复与强化 + 对手多样性评估

> 提出：用户（2026-09-11）｜原则：**我们不是只打黄队；修好黄队、让陪练更强，同时不得损害我方策略。**
> 本文是规范（spec），实施前提：本机 shell 恢复（当前 `0xC0000142`，无法编译/跑脚本）。

---

## 1. 原则（三条，后续所有改动都按这个裁）

1. **我方策略只做"规则 / 机制"层改动**，不做"针对某个对手套路"的特判。
   - ✅ 合规例子：第 44 轮（执行器加速度极限、制动包线）、第 49 轮（禁止推球区/死球期不推球）、
     route 全局安全性校验、点球旁路（平台规则）。
   - ❌ 需警惕：为"demo 爱控停门前"而写的特判（`chase_target` 幻影球校验、门区纪律里的具体坐标），
     要能说清"这是规则约束"而不是"这是对付 demo 的技巧"。
2. **陪练的职责是"打得像真对手"**：不乌龙、不僵局、不靠判罚中断比赛，同时**有真实进攻威胁**。
   陪练送分 = 训练数据失真，比"陪练太强"危害更大。
3. **评估必须跨对手**：任何我方改动都要在**多个对手档位**上验证不劣化，而不是只看
   `scripted × strength 2.0`（这是我们目前唯一的档位 —— 过拟合风险来源）。

## 2. 黄队（陪练）现状与问题

### 2.1 已做的改动（第 48 轮 v2，已部署）
- 保留（**禁区位置限制**三道）：① 门区 y 带内目标 x ≤ 164；② 大禁区最多 1 人（非最近球者 x ≤ 135）；
  ③ 实际位置踩进 x ≥ 168 立即退回。
- 删除：④ 门将保护圈、⑤ 蓝队死球全队退回 x ≤ 130（后者的副作用是"全队每次重启后撤"→ 观感变慢）。
- 修：门球落点 `(10,70)` → `(10,90)`（原落点压在门柱线上，导致门球死锁）。

### 2.2 遗留问题（用户实测反馈）
| 现象 | 状态 | 影响 |
|---|---|---|
| **黄队乌龙球严重** | 未修 | 陪练送分 → 训练失真 |
| 门球死锁（一场连续 8 次 `Goal Kick Yellow`） | 已修（落点） | 待验证是否真的不再循环 |
| 压迫强度低于原版 demo | 由 v2 删 ④⑤ 造成 | 陪练变弱 |

### 2.3 乌龙的三个候选机制（需 rlg 判定，工具已就绪）
用 `tools/web/rlg_probe.html`（双击即用，纯前端解析 .rlg）看每个进球的**最后触球者**：

| 机制 | rlg 特征 | 修法 |
|---|---|---|
| **M1 门球/自家门前乱碰** | 最后触球 = `yellow`，触点 x ≈ 5~25、y ≈ 75~105，出射方向朝自家门线 | 见 §3.1（自家门前禁止反向推球 + 门将程序化开出） |
| **M2 我方射门被挡变线** | 最后触球 = `yellow`，但**出射方向与朝门方向偏差很小**（<15°）且球速高 | **不是乌龙**，是我方射门奏效；不动 |
| **M3 门将"只站位不推"** | 最后触球 = `yellow[0]`，机位在球与门之间、球速≈0~20 | 见 §3.1（门球/清球必须"穿球推出去"） |

⚠️ 平台只记"球越过哪条线"，不记谁碰的 → **归属必须靠最后触球者判断**（这就是 rlg_probe 的作用）。

## 3. 黄队的"修复"（不加特判、让它更耐打）

### 3.1 自家半场球权安全（对应我方第 49 轮的同类修复）
规则层动机：**任何队伍都不该在自家门前把球推向自家门线**（乌龙 = 白送分）。
在 demo 的 `Position()` 里加一条（与禁区三道闸同一处）：
- 球已在本方罚球区（x ≤ 20 且 y∈[62.5,117.5]）时：
  · **外场球员禁止推球**（退回/站开），把球交给门将处理；
  · **门将**：若球在本方门区且自己已贴球（≤25cm）→ **直线穿球推向 +x**（朝场心），
    不许"只站到球的位置"（这正是门球死锁的成因）。
> 这条是"让陪练更强"的核心：**减少乌龙 = 提高陪练的有效防守**。

### 3.2 门球/清球程序化
- 我方（对方）门球：门将站球后 (球.x − 8, 球.y)，下一帧直线推到 (球.x + 30, 球.y)。
- 与 §3.1 共用"穿球推"实现，避免再加一套分支。

### 3.3 恢复压迫（把 v2 删掉的强度补回来，但**不恢复导致判罚的部分**）
- 不恢复：⑤"全队死球后撤"、④"门将保护圈"（这两条是判罚打断的来源，且非位置限制）。
- 补回来（**只在前场**）：对方半场的追球人数从"全员"改成"最近 2 人"（现在 ② 已限制大禁区 1 人），
  保证前场有压迫、后场留人 —— 这既提升强度，也降低"3~4 人挤门前"的判罚风险。
- 可选（风险更高，单独一轮）：加"回传/解围选择"（把球传给空位队友而不是一味带）。

### 3.4 明确不做的事
- ❌ 不把我们的战术（对准纪律、远射档阈值等）搬给陪练 —— 那会把陪练变成"另一个我们"，
  丧失"打不同风格"的训练价值；**要不同风格，用 §4 的人格参数，而不是复制我方策略**。

## 4. 对手多样性（"各种类型的队伍"）

### 4.1 sim 侧：对手矩阵（现在只有一个档位）
`sim_bench` 已支持 `--opp scripted|self|yellow|wall` + `--strength X`，但我们的 A/B **只用过
scripted×2.0**。改为**矩阵评估**，任一改动必须在这张表上都不劣化：

| 对手档 | 命令 | 代表什么风格 |
|---|---|---|
| 弱脚本 | `--opp scripted --strength 1.0` | 松散队 |
| 中脚本 | `--opp scripted --strength 2.0` | 现基线（≈demo 强度标定档） |
| 强脚本 | `--opp scripted --strength 3.0` | 高压队 |
| 门线堆人墙 | `--opp wall` | demo 式 5 人墙 / 摆大巴 |
| 自我博弈 | `--opp self` | 同强度镜像（暴露对称性缺陷） |

判据：**每个档位 Δ 净胜 ≥ -0.5（单档噪声内），且矩阵平均不劣化**；任何单档劣化 >1.0 必须解释清楚
（是真回归，还是该档位本身不适合这个改动——例如远射档在弱脚本门将前天然吃亏，docs/03 有前科）。

### 4.2 真机侧：三档陪练人格（黄队 DLL 变体）
用同一个 `patch_demo_yellow.py` 的 `--persona` 生成三个 DLL，按训练目标切换部署：

| 人格 | 参数倾向 | 训练目的 |
|---|---|---|
| **S1 高压逼抢** | 前场追球 3 人、大禁区不限人 | 练我方出球与传球链抗压 |
| **S2 深防反击**（默认，接近现 v2） | 后场堆人、前场只留 1 人 | 练我方破密集防守（我们最缺的能力） |
| **S3 全场人盯人** | 每人盯最近对手、不追球 | 练我方个人摆脱与二过一 |

部署方式：DLL 编译到 `C:\Strategy\.tmp\opponents\<人格>\`，用一个 `tools/py/switch_opponent.py`
（待写）把选定人格复制成 `C:\Strategy\Strategy4Yellow.dll`（**保留备份**）。
> 合规：demo 源码与变体**只在 `C:\Strategy\.tmp`，绝不进仓库、绝不进提交材料**（AGENTS 原创红线 #1）。
