## 1. FIRA 论文

### SOME ADVICE ON FIRA'S SIMUROSOT（2007，Xun Li 等，武汉工程大学/哈工大）

**主题：** FIRA SimuroSot 仿真平台的历史、缺陷与改进建议。平台屏蔽了机器人硬件差异，队伍只需专注路径规划、避障、策略算法。

**平台历史：**
- **11v11 大场地（Large League）**：哈工大（HIT）开发，2001 年北京第 6 届 FIRA 世界杯首次官方使用。C/S 结构 + UDP 通信，碰撞检测与动力学模型 HIT 自研，2003 年加入裁判模块，常用版本 2003-09-04
- **5v5 三维平台**：2002 年 3 月澳大利亚 Griffith 大学 RSS 开发组发布，基于 Macromedia Director 8.5，物理引擎 Havok，经 dll 与客户端交换数据

**发现的平台缺陷（对做仿真策略的启示）：**
1. **大场地碰撞模型**：机器人与球、场地斜边互相穿透；球撞机器人后第一周期随机运动；机器人互撞可能死锁；球常卡进四角直到自由球才出来
2. **半场不对称**：左右半场对抗存在明显差异，同样策略左半场占优
3. **物体比例失真**：实测场地 1032x818 像素、机器人 13x13、球直径 8，相对场地比真实 MiroSot 偏小，建议对齐 MiroSot 尺寸
4. **中场地碰撞后速度衰减过快**：球撞边界垂直方向速度骤减（例：(2.40,1.62,2.89) → (0.42,1.31,1.37) cm/cycle），边界附近易僵持
5. **碰撞判罚争议**：5v5 3D 视角不同角度结论不同，进球前常有争议，建议平台自动判罚
6. **位置判定争议**："物体 50% 以上在区域内才算在区域内"的规则 3D 视角下难判，建议平台自动判定
7. **摆位耗时**：球/机器人手动摆放，频繁"摆位—犯规—重摆"，建议程序自动归位
8. **缺自动裁判**：5v5 建议加自动裁判（对标 11v11），提供官方公开的裁判脚本编辑器

> 启示：FIRA 5v5 平台物理模型有历史怪癖（碰撞衰减、卡角、穿透、半场不对称），策略设计必须预期这些平台行为，而非理想物理。

### 2.1 HELIOS（2021 / 2022 / 2023）

#### HELIOS 2021：Matchup 位置交换 + 分布式评估系统

**一句话贡献：** 基于球员间 **Matchup（对位关系）** 的 **Position Exchange（位置交换）**：比赛中识别己方/对方球员对位，交换己方异构球员（能力参数不同）位置，制造更多"己方能力占优"的对位；配套 client-server 交互式 **Team Performance Evaluation System**。

**架构：** 三角剖分阵型模型（Formation Model using Triangulation，负责站位）+ 动作序列规划（Action Sequence Planning，在线协作决策核心）+ 评估函数（论文承认"获取有效评估函数仍是待解决问题"）；Coach Agent 赛前决定每球员的 Player Type；新增 Position Exchange 模块与评估系统（Slack bot API 接收请求 → server 按 CPU 占用分发给空闲 host → 跑模拟器/分析日志 → CSV 汇总 Google Sheets）。

**关键技术点：**
- **Matchup 识别**：赛前不知对方阵型/策略，用"我方球员与其最近对方球员构成对位"的启发式，开局尽快识别，不要求一一对应
- **两种交换规则**：all 规则（同角色组 Forward/Midfielder/Defender 内按 30m 冲刺能力排序，强对强弱对弱）；specialized(sp) 规则（组内最快专对对方最慢，其余仍按 all）
- **实验**：HELIOS2019 基底、10 个高跑动 player type，六种设置（NOSWAP/DF all/MF all/FW all/FW sp/COMB）× 各 1000 场（随机种子）对 CYRUS/YuShan/HillStone/JyoSen/Shibaura 五对手；**DF all 与 COMB 显著（5% 显著性检验）降低对方进球与直塞次数**——防守端位置交换收益最稳
- **评估系统价值**：模拟赛随机性大，需海量比赛才能统计出胜负，该系统把"跑 1000 场+统计"自动化，开发以统计指标为闭环依据

**差异/创新：** 对手（Fractals2019 组合优化、Team Titans 搜索算法）把异构球员分配当全队组合优化；HELIOS 下放到个体对位、比赛中动态交换。评估体系多数队伍人工跑赛，HELIOS 做成了可远程交互的分布式流水线。

#### HELIOS 2022：队名效应实证（对手身份影响策略与结果）

**一句话贡献：** 大规模统计实验证明并量化**对手队名对策略与结果的影响**：收集 RoboCup 2021 前 13 强队伍二进制，Anonymous（双方不知队名）与 Non-Anonymous（知队名）模式各跑 1000 场循环赛，卡方检验等手段验证部分队伍（含 HELIOS 自己）仅凭队名就切换针对性阵型策略。

**关键技术点：**
- **Opponent-Specific Strategy**：同一对阵，知道对手队名时 HELIOS 开球阵型与匿名模式明显不同——已发展出针对特定队伍的专门化策略；论文认为联赛进入"针对化开发"第二阶段
- **匿名对照实验设计**：这是"队名效应"的干净消融——策略若真依赖对手身份，匿名后应出现可检测的统计差异
- **胜率差异分析**：HELIOS2021 积分 32.188→32.281 仍居第 1；Oxsy 21.688→18.656 从第 5 跌第 6；FRA-UNIted 17.375→19.219 从第 6 升第 5；**Chi-squared test 两轮检验**（胜/非胜二分 + 胜/平/负三分，两轮显著记 1 分、一轮 0.5 分、均不显著 0 分）生成显著性热力图
- **行为四参数检验**：final point / domination time / pass 数 / dribble time；流程 Shapiro-Wilk 正态检验 → F 检验方差齐性 → Student/Welch t-test 或 Mann-Whitney U；**胜率显著变化的队伍行为参数同步显著变化**（如 CYRUS、Oxsy）
- **方法学反思**：双匿名无法区分"我方变还是对方变"，计划做**单侧匿名**实验归因

**差异/创新：** 不是新战术而是"联赛元分析"，把假设检验系统化用于揭示策略针对化现象，为联赛规则（是否匿名）提供实证依据；13 队二进制 + 1000 场×2 模式日志库即后续 opponent modeling 素材。

#### HELIOS 2023：Learning to Rank 学追球决策

**一句话贡献：** 把信息检索的 **Learning to Rank（LTR）** 引入最频繁行为 **Ball Chasing（追球/接球）**：LightGBM（LambdaMART 的梯度提升树实现）在 15 维特征上训练排序模型，从多个候选接球位置（ball trap position）与姿态中选团队最优，NDCG@10 验证约 10 万条数据即可复现人类设计的评估函数。

**关键技术点：**
- **为什么需要 LTR**：单纯追球早期 RL 即可解；但接球者还要选哪个 **ball trap position + posture** 对团队有利（例：左→右进攻角色的 10 号球员，接球点应选更靠对方半场），多目标权衡传统只能手工规则
- **建模**：query = 场况快照，documents = 候选行为（Omnidirectional/turn/dash 组合）；LTR 直接以排序质量（NDCG）为目标，比回归/分类贴决策本质；梯度提升树优于此前 **SVMRank**（SVMRank 难处理例外情境、须补规则）
- **15 维特征**：动作类型、turn/dash 次数、接球所需步数、**接球时距球距离**、接球时剩余体力、接球时球 X、**offside line X**、接球点距对方球门距离、对方/队友最短到达步数、我的移动距离、**kickable area 半径**、当前/接球时球速——来自 HELIOS2021 实战使用的手工评估函数
- **训练数据（模仿学习）**：记录模式下运行，把"手工评估函数选出的接球点"写入日志当标签；HELIOS2021 的 10 号球员 100 场共约 20.7 万条（2/5/10/15/50/100 场六档：5826…206974 条）
- **结果**：数据增大 NDCG@10 单调上升，**约 50 场（≈10 万条）后不再显著增长，NDCG@10 ≈ 0.99**（105534 条时 0.992）
- **特征消融**：**Feature 4（接球时距球距离）最重要**（移除后 NDCG 降至 0.892，开发者都意外）；特征 2/5/6/10/13/14 几乎无贡献可删减
- **诚实边界**：能复现既有评估函数，未证明线上更有效；未来装入真实 agent 在线比赛，支持 imitation + external instructions

**差异/创新：** 首次把 LTR（LightGBM/LambdaMART）当 2D 仿真足球决策工具；把"RL 就能解决的追球"重新定义为战术决策问题（位置+姿态的团队最优）；日志模仿学习 + 特征消融双结合，直接指导特征工程与数据量。

#### HELIOS 纵向对比（2021→2023）

- **不变骨架**：HELIOS Base + 三角剖分阵型 + 动作序列规划三件套贯穿三年；**评估函数是始终未解难题与主攻方向**（2021 承认待解决 → 2022 行为统计 → 2023 换武器 LightGBM）
- **方法论**："海量比赛 + 统计显著性检验"一贯风格（1000 场×6 设置 / 13 队×2 模式循环赛 / 100 场日志 + NDCG）
- **演进主线**：2021 个体对位优化（位置交换）→ 2022 对手身份影响实证（为针对化策略提供动机）→ 2023 用 LTR 把针对对手的战术决策下沉到单个追球行为并自动化
- **ML 工具链升级**：人类选择学习/MLP（2018/2020）→ SVMRank → LightGBM/LambdaMART（2023 换挡，选可解释、能处理异常、工程成熟）

### 2.2 CYRUS（2021 / 2022 / 2023）

#### CYRUS 2021（当年冠军）：Kick Behavior Predictor（行为预测器）

**一句话贡献：** 球权者基于带噪观测（noisy observations）用 DNN 预测其在无噪 **Full-state World Model (FWM)** 下的完整行为（传球目标等），并把预测用于**最优视角选择**，期望胜率 +11.30%（实测 8.19%→17.49%，进球率 0.45→0.89）。

**架构：** agent2d（Helios 系）基座。
- **WM/FWM 双模型输入**：服务器 full-state mode 同时下发带噪 WM 与纯净 FWM；球不可踢时 Move 决策只用 WM；球可踢时 Kick 决策把 WM 交给 Data Extractor、把 FWM 交给 Chain Action（基于纯净 FWM 选最优动作）
- **Data Extractor** = Feature Extractor（从 WM 提特征）+ Label Generator（把 Chain Action 动作转标签）
- **特征体系**：球侧（位置/速度/方向、Dribble Free Distance）、全局（Cycle、Offside count）、球员侧（Body/Face/Tackling/Kicking/Card、Player Type 物理参数 DashRate/Effort/KickableDist/KickPowerRate/Decay/Size/SpeedMax、位置速度极坐标、PosCount/VelCount、FreePassAngle/DirectPassDist、FreeShootAngle 等）
- **标签体系**：Category（Hold/Pass/Dribble）、TargetUnum、TargetIndex、Description（Dribble/Direct Pass/Cross/Through/Lead Pass）、TargetPosition、FirstKickAngle/Speed
- **训练**：Cyrus vs Helios2019 共 100 万条，Keras 训练，自研 **CppDNN** 把权重转文本在 C++ 重建（Eigen 计算）

**关键技术点：**
- **"预测 full-state 行为"替代"直接降噪"**：三模式对照证明噪声主导胜负——Normal 胜率 7.09 / 期望 8.19，Chain Action 用 FWM 24.64 / 33.46，全 FWM 72.7 / 85.76。CYRUS 用带噪观测直接学"无噪世界最优行为"，等于隐式降噪且输出可直接用
- **Player Feature Sorting（10 种排序）**：X / X-FK / Unum / Unum-FK / AFC / AFC-FK / AK / AK-FK / AKG / AKG-FK（**FK = Kicker 恒排第一**）；**Unum-FK 精度最高**（Category 77.37%、Unum 60.57%、Description 71.62%）——多智能体输入的表征顺序本身是重要超参数
- **特征价值分析**：Random Forest + Permutation Feature Importance（ELI5）
- **预测驱动感知调度**：在线用 Unum-FK 预测"full-state 下目标接球球员 Unum"，球权者对该球员信息不准（PosCount 大）时优先观测他——预测网络用于观测调度而非直接改动作

**差异/创新：** 把 DNN 行为预测闭环嵌入感知-决策流水线；系统研究特征排序影响（10 方法对照）。开源 CppDNN（Keras→C++）、Starter Agent/LibRCSC、Pyrus（Python 全功能 base 支持 full-state）——面向新队与 ML 研究者，圈内少见。

#### CYRUS 2022（当年亚军）：Pass Prediction DNN 驱动 Unmarking

**一句话贡献：** 球员用 DNN 预测"未来谁会传球给我"，经 **Best First Search** 在传球-状态树上推演确定**传球人（Passer，Decisioning）**，再搜索最优接球点（Positioning），期望胜率 +约 5%，控球率与射门数同步上升。

**架构：**
- 数据采集延续 2021：Data Extractor = Features Extractor + Label Generator（Chain Action 输出转"最佳传球目标 Unum"标签）；**Player Sorter：对手按 x 坐标、队友按 Uniform Number**
- **离线训练**：CYRUS vs YuShan2021 共 10,000 场 → 3,000,000 条，80/20 划分；DNN 3 层（350-250-11）ReLU + softmax，测试精度 **73%**
- **在线决策**：Pass Predictor 模块——给定状态与球员列表，输出每个球员的接球概率

**关键技术点：**
- **Unmarking 拆解为 Decisioning + Positioning**：Unmarker 先找 Passer（未来会给自己传球的队友），再找最优接球位置
- **传球树 + Best First Search**：每个无球队员本地模拟树——节点 = 未来某状态（该状态我方某球员为球权者），边 = 一条可能传球；Pass Predictor 接收"状态 + **Ignored Players 列表**"（已当过球权者不能再当接球者，保证树中球权唯一），取概率最高两人封装 **Pass-State-Value**；根节点为当前状态，若球将被队友截获先预测**截球 cycle 与位置**再建根；Best First Search 扩树至 **10 节点**，Unmarker 找到自己的节点，其父节点球员定为 Passer。**价值：不是启发式找空位，而是用队友真实传球习惯的概率模型向前推演整条传球链**
- **Positioning 三级候选点**：以当前位置为中心 3 半径层（2/4/8m）× 每层 8 点；仿真"从 Passer 的传球"，能先于对手接到才"有效"；有效点中选**最靠近对方球门**。两级筛选：可接性 → 进攻威胁性
- **V1–V6 消融**：三种 Unmarking——Pass Prediction（DNN+邻域搜索）、Hard-Coded（球权者距 Unmarker<20m 则其为 Passer，否则取连线附近球员）、Voronoi（找逃离盯防位置）；CYRUS2021 正式版 = Hard-Coded+Voronoi 回退。6 版本 × 1000 场对 YuShan2021：**V1（纯 Pass Prediction）期望胜率最高（3.28 vs 基线 V6 2.85）**，全指标更优

**差异/创新：** 别人把传球预测当分析/评价工具（对手建模、行为评价），CYRUS 把它升格为**无球跑位的直接决策器**，生成可执行的"未来传球链"；DNN 概率 + BFS + Ignored Players 唯一性 + 10 节点剪枝在 100ms/cycle 实时约束下可落地；严格六组合×1000 场消融。

#### CYRUS 2023：LSTM/DNN 观测降噪（通用感知底座）

**一句话贡献：** 用 **LSTM 与 DNN** 对 SS2D 视觉量化噪声建模，输入最近 5 个 cycle 的位置与传感器信息序列，回归预测（主要是对手）球员更准确位置；**LSTM > DNN > 原始 last-seen 视觉数据**。

**架构：** 基座升级 **Cyrus2D Base**（融合 Helios Base + Gliders Base + CYRUS 2021 冠军代码，2022 起开源）。
**噪声建模**：SS2D 视觉三档——Wide 180°（冷却 3 cycle）/ Normal 120°（2）/ Narrow 60°（1）；每物体带 **pos count**（距上次观测 cycle 数）；距离/角度被量化（越远噪声越大、角度浮点取整）。Helios 基线为启发式（按可探测距离平均区间细化估计）；CYRUS 改为数据驱动：**pos count > 1（物体"过时"）时用 ML 预测位置**。
**训练数据**：Cyrus2DBase vs HeliosBase 跑 **400 场**，采集球+22 球员位置/速度/body 方向/pos count，同时记录带噪值与真值。

**关键技术点：**
- **时序输入**：最近 5 cycle 位置+传感器序列 → 输出"失明期间"真实位置；LSTM 隐状态编码运动时间相关性（惯性），能外推 pos count 大的位置，补不了"多帧没看到"的启发式做不到
- **模型选型**：最优 **LSTM 512-256（全 ReLU）** 与 **DNN 512-256-128-64-32**；LSTM 更擅长预测球员位置
- **误差热图评估**：以"未看到 cycle 数 × 观测者距离"为坐标画热图，系统性证明 LSTM > DNN > last-seen，并给出收益适用边界；黑色区域 = 数据不足
- **可迁移性前问题**：模型学历史数据分布，对手阵型/策略变化会降精度；新队出路——(a) 相近队伍预训练模型冷启动，(b) **online learning**（比赛中学对手策略）

**差异/创新：** 回到感知层，用 LSTM 解决所有队伍都面对、大多用启发式应付的"视觉量化噪声+视野冷却"问题；兑现 2021 Future Work 的 RNN 规划；开源生态顶级：Cyrus2D Base、PYRUS、AutoTest2D（并行批量测试）、AutoTune2D（调参）、Cyrus Log Analyzer——"刷数据-训练-调参-评估"全流程工具化。

#### CYRUS 纵向对比（2021→2023）

1. **焦点演进：行为预测 → 动作决策 → 感知重建**。2021 预测球权者 full-state 行为用于视角优化（间接）；2022 同套思想变无球跑位直接决策器（Pass Predictor + BFS 传球树）；2023 落到最底层对手位置时序降噪。方向是"决策高层的智能 → 感知底座的无偏"，把 ML 做成感知-决策全链路
2. **模型形态：前馈 DNN → 更深 DNN → 循环 LSTM**（2021 多任务网络；2022 3 层 350-250-11；2023 LSTM 5-cycle 输入）
3. **数据工程作坊→流水线**：100 万条手工造（10 种排序对比）→ 300 万条/1 万场（固定排序规则）→ 400 场带噪+真值配对；工具逐年补齐 CppDNN → AutoTest2D/AutoTune2D → Log Analyzer
4. **应用闭环逐步做实**：先"观测谁"（view angle）→ "去谁那接球、站哪"（unmarking）→ "所有物体位置更准"（通用感知底座）；每年有量化消融（三模式对照 / V1–V6×1000 / 热图）
5. **从建模自己到建模对手**：预测队友行为 → 预测队友传球链 → 预测对手位置，Future Work 预告 online learning 学对手策略
6. **成绩与基座**：2021 冠军、2022 亚军；base 从 agent2d 演进为 Cyrus2D Base 开源，团队转型为"联赛基础设施输出者"

### 2.3 FRA-UNIted 2023（德国·法兰克福应用科学大学）

**一句话贡献：** 把**基于模型的批量模式深度强化学习（model-based batch-mode deep RL）**落地到 dribble 微观技能——重实现 Soccer Server 动力学做状态转移建模，用 **fitted value iteration (FVI) + 神经网络价值逼近**，在数据效率上证明 growing batch 可超越手写与在线 RL 策略。

**架构：** world module（近似完整全局状态，particle filter 改善自定位）+ decision making module，整体为 MDP；行为架构层次化但不严格（低层行为可回调高层行为，如拦截可把决策权交回 defensive behavior）；大量行为 RL 习得，沿用 Brainstormers（Riedmiller 1998）工程遗产。

**关键技术点：**
- **高效状态转移建模**：轻量 C++ 重实现 Soccer Server 动力学（kick/dash/turn/tackle、球碰撞、基础噪声），绕过进程间通信直接算后继状态 s′：**平均 0.137µs/次，单核 3GHz 每秒建模 730 万次转移**——model-based RL 能大规模采样的前提，学习完全在 agent 内部
- **Dribble BRL 任务**：状态 7 维（球相对位置/速度 4 + 球员速度 2 + 角度偏差 1），动作离散化 **576 个 kick/dash/turn**；即时奖励 = 沿 dribble 目标方向的速度分量
- **FVI 实现细节**：4 层 MLP 价值逼近；每轮 FVI 用 **Rprop 只训 5 epoch**、**迭代间不重置网络**让价值缓慢演化；γ=0.9；暂在无噪声环境
- **Pure batch vs Growing batch**：纯批量（2k~200k 固定样本）不收敛/波动大，达不到手写（无噪声 81.67m/100 步）与在线 RL ND17（79.81m）；**growing batch（b=20k 起步收集到 100k）无噪声环境 82.41m 反超**——"用当前贪心策略采样扩充数据集、让学习聚焦状态空间相关区域"是数据效率关键
- **CI 系统**：支持任意队伍二进制与配置参数，避免只对同一对手测试的 **overfitting**；用 **local outlier factors + isolation forests** 识别严重偏离预期的 outlier 比赛（能检出 gold standard 近一半）
- **SSV 17 规则变更应对（门将）**：SSV 17.0 禁 dash power=−100、门将 catch 限身体朝向 ±90°（此前可接身后球）——两项曾是门将沿门线快速移动的基础。适配后对 Helios2022 从 0.27:6.14 提升到 0.66:2.05，得失球比 22.85→3.11；被射门丢球从每 2 次丢 1 球改善为每 5 次丢 1 球；顺带发现防线身后被打穿的 1vs1 门将问题

**差异/创新：** 2023 四队中唯一真正在跑 RL 训练（价值函数逼近 + Bellman 更新）；独特之处是**显式模型化**——重实现动力学近乎免费算 s′，把数据效率当第一研究目标（BRL 卖点：可用任意甚至随机策略采样的数据学习）；CI + outlier 检测把"评估"工程化；研究导向。

### 2.4 YuShan 2023（中国·安徽工业大学）

**一句话贡献：** 提出**基于核密度估计的负例学习方法（KDE negative example learning）**，对比赛日志（RCG/RCL）提取的传球动作做特征增强与分类，挖出进攻关键区域并优化传球/接应决策，提升进攻强度。

**架构：** 基于 YuShan_Base（Agent-2D 3.1.0 + 新版 librcsc）；此前提出 **digital twin 框架**（数据挖掘给队伍画像，测试结果反馈代码改进）。数据管线：RCG（坐标/速度/角度等参数）+ RCL（球员动作与参数）→ 解析动作链 → 提取有效传球 → 分类建模 → 在线决策优化。决策落地用**粒子群优化（PSO）**把传球接应点/动作触发关系拟合成**多项式**，供球员在线判断。

**关键技术点：**
- **为什么需要负例学习**：传球模块参数复杂、数据分布高异构，直接分类效果差；传球触发点呈簇状聚集，需把离散点集转连续分布消误差
- **KDE**：非参数估计，**Gaussian kernel** 把二维传球触发点集映射为连续概率分布面；带宽 h 由 **Scott's Rule** h = n^(−1/(d+4)) 自动确定；KDE 把不同大小点集归一化到同一量级，消除数据集规模差异
- **负例学习算法（核心创新）**：①按传球方向分 n 类，每类随机分 m 子类，得 m×n 个数据集 D_{i,j}；②每子类拟合分布 f_{i,j}；③特征提取编码器 g(·) 得子类特征 h_{i,j}；④多分类分解为多个二分类：同一统一类的子类为 data class、其余为 noise class，损失 **L_D(i₀,j) = −log(Σ_j e^{h_i₀,j/γ} / Σ_i Σ_j e^{h_i,j/γ_i})**。**温度系数 γ_i 是关键**：类间越近 γ 越大（损失更平滑），类间越远负样本惩罚越大——放大不同类点集分布概率差，把堆叠难分的分布"分层"，强化各自特征
- **数据定义**：传球 = 日志中不同球员的一串 kick（第一脚踢出、第二脚反向停球）；带球 = 同一球员 kick+dash 组合；**成功动作链 = 链末端为射门**，其中传球记为有效传球
- **实验**：2022 世界杯 Day4 的 HELIOS2022/CYRUS/HfutEngine2022/MT2022 为基准队打 200 场，按传球方向分 8 类；接应点优先选传球触发概率高的区域（如持球者在边角时，接应者站同侧禁区边缘、自由前锋向禁区中路移动），传中后可立即二次出球形成连续快攻
- **结果（30 场测试）**：HELIOS2022 净胜 +0.4、失球 −1.0、传球触发率 +3.89%；CYRUS +0.6/−0.8/**+16.61%**；HfutEngine2022 +0.0/−0.4/+6.15%；MT2022 **+1.2**/−1.0/+2.94%；四队有效传球数均提升

**差异/创新：** 2023 四队中唯一走**数据挖掘/离线统计**路线优化战术：不训策略模型，把己方传球轨迹做成"面对不同对手的概率画像"，**负例学习放大类间差异**；digital twin + PSO 多项式是工程特色。

### 2.5 Hades2D 2023（伊朗·德黑兰 Farzanegan 中学）

**一句话贡献：** 把**球门划分为 24 区域**并评分射门路线、计算各区域 **shootability（可射性/进球概率）**、对传球接应者排序 + **三角分区阵型**，提升射门/传球清晰度与站位合理性。

**架构：** 基于 **starterAgent**（教学简化版 Agent2D/HeliosBase），沿用 Hades2D 2021 传球策略；模块：Shoot / Shootable / Pass / Formation。

**关键技术点：**
- **Shoot**：球门分 **24 区域**，剔除**门将所在 1/4 区域与次要路径**，按三判据评分：①球与门将距离、②门将位置、③球与对手球员距离，选最优路线
- **Shootable**：复用 24 区域，基于球员与目标间**角度**算射向每个区域的进球概率，射概率最高区域
- **Pass**：接球者选择看——①附近对手数量、②接球者到对手距离、③传球距离可用上限、④附近可用队友；打分排序选最高
- **Formation**：球场划**三角形区域**，按球所在三角区域决定站位布局
- **Future ideas**：deep pass pattern；评分选 deep/side pass 最佳点；**blocking/unblocking**——己方球员挡对手跑动路线使其接不到传球，强化防守

**差异/创新：** 四队中最小、最教学化（中学生队伍、首次参赛）；**纯启发式评分 + 几何划分，无任何 ML/统计**；借鉴 HillSTONE 2019 角度射门思想；与 RoboCIn 几何拦截、YuShan 概率分布属不同技术代际。

### 2.6 RoboCIn 2023（巴西·伯南布哥联邦大学 CIn，两届 LARC 冠军）

**一句话贡献：** **Voronoi 离散化 + Hungarian algorithm（匈牙利算法）**实现前锋站位与角球防守的自适应指派，加 **Defensive Ball Interceptor** 与重写门将，配套 **Docker 容器化并行测试/日志分析模块**做大规模统计验证。

**架构：** agent2d 3.1.1 + gliders2d-v1.6（改善移动）+ MarlikBlock；调研 Cyrus2D。模块：前锋站位、角球动态防守、Defensive Ball Interceptor、门将（双方案）、容器化测试模块。开源：**SoccerAnalyzer**（自家日志统计）、soccer-common（Small Size 开源实现，匈牙利算法来源）。

**关键技术点：**
- **前锋站位**：**Voronoi 离散化**（Gliders 提出，以对手位置为 site 划分候选进攻点）→ 以球为圆心**圆周过滤**精简候选 → **匈牙利算法**（多项式时间求解指派问题）把前锋指派到圆周内最近点。把"谁站哪"变成最优指派问题，避免贪心乱配；**500 场测试胜率 34.96% vs 开发版 31.43%，Goal Balance +17**
- **角球动态盯防**：旧方案只用阵型文件静态站位；新方案角旗区半径内防守球员就近调整到**最近未盯防对手**，再匈牙利指派。**丢球率 6.8%→3.5%，角球拦截率 26.0%→71.0%**，角球区夺球率 72.1%→74.0%
- **Defensive Ball Interceptor**：灵感 **Tehran 2022 TDP**；针对对手长传穿透防线，利用**球门线-球-球员向量集 + 球运动方向**判断动作是否合适并预测**最佳拦截点**，指挥最近队友到球的运动点切断进攻
- **Goalkeeper（应对 SSV 17.0.1）**：旧门将大角度进攻会停在门柱旁留空门；按 Helios 思路重写两个门将：**GK1**（按球是否朝向球门分行为，球不来时左右移动**最大化可接球面积**，射来无论成功率都尝试接球）、**GK2**（简化版拦截器追踪最优拦截点）；首次加 **omni-directional movement**。500/1000 场对比 **G1 明显更优**（胜率 38.51% vs 33.58%，Goal Balance +82 vs −156）
- **Testing Module**：**Docker 容器**隔离 RoboCup 2D 环境、跨平台一致；根主机按配置并行跑指定场次与对手，结束后收集分析日志；支持离线教练预置训练场景；输出 Victory/Defeat/Draw/Score/Goal Balance/Score Per Game 统计表，每次约 **500 场**

**差异/创新：** 四队中唯一把"工程基础设施"当核心贡献（Docker+并行测试+日志分析器+SoccerAnalyzer）；方法论是**运筹学指派（匈牙利）+ 几何预测（Voronoi/拦截向量）**而非学习算法；与 YuShan 同为日志驱动，但 YuShan 做概率建模、RoboCIn 做统计验证与工程化。

### 四队横向对比（2023）

| 维度 | FRA-UNIted | YuShan | Hades | RoboCIn |
|---|---|---|---|---|
| 主攻问题 | 数据高效的 RL 微观技能（dribble） | 传球策略离线数据挖掘优化 | 射门/传球/阵型启发式清晰化 | 自适应站位盯防 + 测试基础设施 |
| 方法论 | model-based batch RL（FVI+MLP） | KDE 负例学习 + 数字孪生 + PSO | 几何分区评分（24 区域/三角阵型） | Voronoi+匈牙利指派 + 几何拦截 + Docker CI |
| 学习/建模程度 | 高（价值函数学习） | 中（统计密度建模） | 低（无学习） | 低-中（无学习，统计验证） |
| 评估手段 | CI 系统 + outlier 检测（LOF/Isolation Forest） | 200 场数据挖掘 + 30 场对照 | 未给出系统评估 | Docker 并行约 500 场统计 |
| 队伍定位 | 研究导向（大学） | 研究+工程（大学） | 教学导向（中学） | 工程+数据科学（大学） |

- **各自主攻**：FRA-UNIted 攻"学习"（最少数据、模型已知条件下把 RL 稳定训进比赛代码）；YuShan 攻"情报"（日志离线挖己方传球习惯与对手差异反哺战术）；Hades 攻"清晰度"（几何分区把决策变可解释评分）；RoboCIn 攻"适配与工程"（指派算法让站位随对手动态变化 + 容器化测试量化验证）
- **方法论异同**：共同点——都站在开源基座（Agent2D/Helios/librcsc/starterAgent）上做**单模块增量优化**而非重写全栈；都依赖**海量对局统计**评估（CI/200 场/500 场），2D 仿真随机性使样本量成为共同前提。分水岭在"用什么产生改进"：价值函数学习（FRA-UNIted）vs 密度估计+负例学习（YuShan）vs 最优指派+几何预测（RoboCIn）vs 手工评分（Hades）——"学习型 → 统计型 → 算法型 → 经验型"的建模强度光谱

### 3.1 NuBot 中型组仿真赛完整工程（DDDDangbu-中型组比赛总结）

**背景：** 中国机器人大赛暨 RoboCup 世界杯中国赛中型组仿真赛（5v5，ROS+Gazebo）。参赛者独立实现 `robot_code/nubot_control/src/` 下全部策略代码：**18 个核心模块、3000+ 行 C++11**（ROS Kinetic / Gazebo 7 / Ubuntu 16.04）。

**5 层架构：**
1. **控制层** `nubot_control.cpp`：**15ms 高频控制循环**、比赛状态机（STOPROBOT/STARTROBOT/KICKOFF…）、ROS 消息收发、全局信息融合
2. **策略层** `strategy.cpp` + `role_assignment.cpp`：战术选择（传球→射门→角色执行三级判定）；**角色分配：距离优先**（离球最近当主攻手）、区域防守分配、动态切换
3. **规划层** `plan.cpp` + `subtargets.cpp`：全向移动控制、动态避障、目标导航；子目标序列分解
4. **行为层** `behaviour.cpp` + `bezier.cpp`：运动基元、速度/加速度控制（P 控制+限速）、**贝塞尔曲线**平滑轨迹
5. **角色层**：Active（追球→带球→射门/传球状态机，射门角度计算、守门员位置预测）、Assist（接应点计算、传球路径分析、拉扯空档）、Passive（区域防守、轨迹预判拦截）、Midfield（中场覆盖、攻守转换）、Goalie（位置调整、扑救预判、解围）

**传球系统：** `passstrategy.cpp` + `staticpass.cpp`。决策三条件：队友在合适位置 + 传球路径不被阻挡 + 自身受压迫。支持静态/动态传球（动态用位置预测提前算接球点）。

**技术亮点：**
- 分布式决策：每机器人独立决策、ROS 话题共享信息，去中心化角色分配，避免单点故障
- 四层状态机：全局（比赛阶段）→ 策略（战术）→ 角色（行为）→ 动作
- 15ms 实时：周期内完成感知-决策-规划-控制全流程
- 智能传球 + 全向移动 + 动态避障 + 贝塞尔平滑

**调试方法：** `rostopic echo /nubot1/nubotcontrol/strategy`（策略信息）、`actioncmd`（运动指令）、`rqt_graph`、`rosbag record -a`。启动：`roslaunch nubot_gazebo game_ready.launch` + `rosrun nubot_common cyan_robot.sh` + `rosrun auto_referee auto_referee -1`。

**难点突破：** 15ms 实时（优化算法复杂度）；多机抢球冲突（距离优先角色分配）；动态传球时机（位置预测提前算接球点）；对手差异大（自适应策略微调）。

### 3.2 FIRA SimuroSot 训练课程（ayozzet-FIRA培训）

## 4. 总结：能"赢"的共性

### 4.1 六条共性（跨 FIRA 论文 / 2D 冠军 TDP / 中型组工程）

1. **开源/官方基座 + 单模块增量优化**：HELIOS Base、agent2d、Agent-2D/librcsc、starterAgent、gliders2d——所有强队都站在共享基座上，只做增量（一个传球模块、一个追球决策、一个门将），没人重写全栈；FIRA 中型组同样基于官方仿真平台只补策略代码。**增量可验证、可回退，是持续迭代的前提**
2. **海量对局统计是唯一可信评估**：HELIOS 1000 场×设置、CYRUS 1 万场/3M 样本、YuShan 200+30 场、RoboCIn 约 500 场 Docker 并行、FRA-UNIted CI+outlier 检测——仿真随机性大，胜负判断必须有样本量；工具化（Team Evaluation System、AutoTest2D、Docker CI、Log Analyzer）把"跑 1000 场"变成日常开发动作。**先建评估基础设施，再谈策略改进**
3. **数据驱动程度分层，先数据后模型**：感知层（CYRUS LSTM 降噪、HELIOS LTR 追球）→ 决策层（传球预测、unmarking、位置交换）→ 模型直接用日志模仿学习（手工函数选出的行为当标签）。ML 引入顺序：先用统计/启发式把基线做对，再用数据学更优决策；特征工程（15 维特征、10 种特征排序）与消融（V1–V6、特征删除）是标配
4. **对手建模 / 针对性策略是顶级队伍分水岭**：HELIOS 2022 证明"队名效应"真实存在且影响胜负；YuShan 用日志给对手画像；CYRUS 预测对手位置 + online learning 预告——"针对谁打"和"怎么打"同等重要，战术要可配置、可随对手切换
5. **层次化架构 + 角色分工收敛**：HELIOS（阵型+动作规划+评估函数）、CYRUS（感知-决策-定位）、中型组（控制-策略-规划-行为-角色四层状态机）——都是"全局战术在上、个体角色在下、评估函数/优先级在中间"。角色化（主攻/协助/防守/守门）、Unmarking、动态盯防等是共通战术语汇
6. **工程基础设施 = 隐形冠军**：HELIOS Slack+Sheets 评估系统、CYRUS 全工具链开源、RoboCIn Docker CI、FRA-UNIted 动力学重实现（0.137µs/次）——强队之间的差距常在这些"不写进论文标题"的部分；开源回流（CppDNN/PYRUS/AutoTest/LogAnalyzer）还让整个联赛生态变强

### 4.2 对 FIRA 5v5 / 中型组仿真项目的可借鉴点（按性价比排序）

1. **先建批量对局 + 统计测试线**（对标 RoboCIn Docker CI / HELIOS 评估系统）：自动跑 N 场比赛、输出胜率/进球/控球/传球数，任何改动先过这条线——这是其他所有点的前提
2. **角色分配上运筹学**（对标 RoboCIn 匈牙利算法、CYRUS 三级候选点）：把"谁站哪、谁盯谁"从贪心启发式升级为可解的最优指派
3. **传球决策加概率建模**（对标 CYRUS Pass Prediction / YuShan KDE）：别只看"路径通不通"，用日志统计"队友/对手下一步最可能做什么"，向前推演 2~3 步传球链
4. **接应跑位评分化**（对标 HELIOS LTR 15 维特征 / Hades 评分）：把"站哪接球"写成可解释评分（距球距离、越位线、对手到达步数、射门机会），再做消融找敏感特征
5. **警惕平台物理怪癖**（FIRA 2007 论文）：碰撞衰减、卡角、半场不对称、3D 判罚争议——策略验证时用统计识别这些系统性偏差，别当玄学
6. **门将单独专项**（对标 FRA-UNIted SSV17 门将、RoboCIn GK1）：规则变更常重创门将，"最大化可接面积移动 + 预判扑救方向"值得独立模块化

**知识点：** 2D 仿真足球的技术主轴可归纳为三层——感知层（视觉量化噪声/视野冷却的降噪，CYRUS LSTM 思路）、决策层（传球/跑位/射门选择，可用 LTR 排序、BFS 树搜索、KDE 概率建模、匈牙利指派四种范式）、评估层（对手建模 + 海量对局统计，HELIOS 队名效应实验是"评估评估方法"的元方法）。model-based batch RL 的可行前提是动力学可重实现（s′ 近乎免费）；KDE 负例学习的核心是温度系数 γ 控制的对比损失放大类间差异；LTR 直接优化排序质量（NDCG）贴合"从候选里选最优"的决策本质。平台物理（FIRA 2007 论文）说明仿真环境本身的怪癖（碰撞衰减、卡角）同属需要建模的对象。
