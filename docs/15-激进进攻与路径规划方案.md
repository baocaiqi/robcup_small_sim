## 2. P0：路径规划层 + 射门机会质量

### 2.1 geometry 扩展（高效原语，全部 O(1)/解析解，不拍脑袋）

新增到 `include/simuro5/geometry.hpp`（+`geometry.cpp` 非 inline 实现）：

```cpp
// 线段 (a→b) 是否与圆盘 (c, r) 相交（含相切）
bool segment_hits_circle(double ax, double ay, double bx, double by,
                         double cx, double cy, double r);
// 线段 (a→b) 是否避开一组圆盘（遍历用，障碍数 ≤5，O(n) 已最优）
// obstacles: 长度 n 的 {x,y,r} 数组
struct CircleObstacle { double x, y, r; };
bool segment_clear_of_circles(double ax, double ay, double bx, double by,
                              const CircleObstacle *obs, int n,
                              CircleObstacle *hit = nullptr); // hit 返回最近挡路者
```

> 遮挡检测（射门路线 / 传球路线 / 路径段合法性）全部收敛到这个原语，替代现在
> pass.cpp 里"点到线段 <15cm 算挡"的手工近似（量纲不清），口径统一。

### 2.2 route 路径规划层（新模块 `route.hpp` / `route.cpp`）

**算法**（传统图论，自研实现，不复制他人代码）：
1. **输入**：起点 S（我方机器人/推球点）、终点 T、≤5 个圆盘障碍（对方机器人，
   半径 inflate = 6cm 本体 + 4cm 净空 = **10cm**；带球场景推球点在身前，
   障碍再 +8cm 视为 18cm，防"人绕过去了球撞人"）；
2. **快速路径**：`segment_clear_of_circles(S,T)` 干净 → 直接返回 [S,T]（直线最短，
   这就是最优，不必进图）；
3. **可见图**：顶点 = S、T、每个障碍圆上**两个切点**（从 S 与 T 各引两条切线，
   圆上切点 ∪ S ∪ T，≤12 顶点）；边 = 任意两顶点线段不穿任何圆盘；
   权 = 欧氏距离（差速轮转向代价一期不做，用切点结构已保证切着障碍边缘走）；
4. **Dijkstra**（V≤12 的稠密图，O(V²)，每帧微秒级）求 S→T 最短路；
5. **输出**：waypoint 序列（≤ 切点数+2），每段都是无障碍直线；含总长。

```cpp
// route.hpp
struct RoutePlan {
    bool found = false;
    double wp_x[8], wp_y[8];   // waypoint 序列（含终点），最长 8 个（V≤12 时理论界）
    int n_wp = 0;
    double length = 0.0;       // 总长 cm
};
// 从 (sx,sy) 到 (tx,ty) 绕开障碍的最优折线；直线可行时直接返回两点
RoutePlan plan_route(double sx, double sy, double tx, double ty,
                     const CircleObstacle *obs, int n,
                     double inflate_margin = 4.0);
```

**执行适配（差速轮）**：motion 层不动（position 本身带转向）；新增
`motion::follow_route(RobotState &r, const RoutePlan &rt, double wp_idx_state...)`
——每帧把**当前最近 waypoint**（离机器人 <8cm 视为到达，切下一段）喂给 position；
到终点段用原来的到位减速。waypoint 切换状态放 WorldModel 每机器人一个 int
（`wp_next[PLAYERS_PER_SIDE]`），防静态量跨帧丢失。

**防抖原则**：目标点每帧重算（球/人动），但只要新路径与上一帧路径第一个 waypoint
距离 <20cm 就沿用旧 waypoint（防 zigzag）；仅当差太大才切换。

### 2.3 plan_shoot 升级：机会质量驱动的动态射程（shoot.hpp/cpp）

**角度遮挡几何模型**（传统几何，解析解）：
- 门柱对球位 (bx,by) 的张角：`angle(bx,by → 门柱A/B)`（A=上柱 (ogx,110)，B=下柱 (ogx,70)）
- GK（取对方离门线最近者）对球位的**遮挡张角**：球位看 GK 圆心 ± atan(R_gk / dist)
  （R_gk = 6cm 本体 + 扑救余量 2cm = 8cm；GK 越出击 → dist 越小 → 遮挡角越大，几何自动量化）
- **有效开口角** = 门柱张角 \ 遮挡张角（两段开口取最大一段；≤0 表示封死）
- **路线遮挡**：球→开口中心 射线 前 30cm 段是否被除 GK 外防守者挡（segment_clear_of_circles）

```cpp
// ShootPlan 增加
double quality = 0.0;   // 0~1 机会质量（决定射 or 继续带/传）
double open_angle = 0.0; // 有效开口角（度）
bool lane_blocked = false; // 射门路线上有 GK 之外的拦截者
double shot_dist = 0.0;   // 射程 cm（球到门线）
```

**quality 公式**（可调参数化，进 docs/06）：

```
quality = w1 * sat(open_angle / kAngleFull)          // 开口越大越好   (w1=0.5)
        + w2 * sat((kMaxShot - shot_dist) / kMaxShot) // 越近越好       (w2=0.3)
        + w3 * sat(ball_speed / kSpeedFull)           // 球越快 GK 越难扑 (w3=0.2)
```
`saturate(x)=clamp(x,0,1)`；kAngleFull=18°、kMaxShot=110cm、kSpeedFull=8cm/帧。
**动态射程**：`open_angle ≥ kMinOpen(8°)` 且 `shot_dist ≤ kMaxShot(110)` 且
`!lane_blocked` → viable；其中 `quality ≥ kShootQuality(0.45)` 为"立即射"档，
quality 中档(0.25~0.45) 且我方带球中 → 继续带球推进逼近（下帧 quality 随 shot_dist
↓ 上升，自然进"立即射"档）；低档 → 传球/拉边。aim_y 不再是 74/106 两选一，
改取**最大净开口的中心线**（连续几何解），射门更准。

> 与 70cm 一刀切的关系：远射不是无条件放开——开口够大（≥8°）且路线通畅才放行，
> 这正是"激进但有依据"；GK 站门线中央封死时远射被拒，避免重蹈 0:3。

### 2.4 run_active 接线（roles.cpp，激进但不莽）

决策优先级（改后）：
1. 门区超限撤出（现状保留，L409-416）
2. **机会质量射门**：plan_shoot viable && quality ≥ 0.45 → 直线推穿（现状执行体）
   ——射程放宽到 110cm 但多一道开口/路线闸门
3. **带球逼近**（新）：带球中（贴球）&& quality 0.25~0.45 → 目标不直接射门，
   用 route 朝"最大净开口中心线的球后推球点"推进（推球点路径绕开拦路防守者），
   逼近到立即射门档
4. 角区救球 / 围困回传（现状保留）
5. plan_pass 传球（现状保留；quality 低 + 传球 viable 时提前到 3 之前？——
   **不**：优先带球逼近，传球只在带球被堵/围困时用——这是"最大化射门"的落地）
6. 追球：chase 目标先用 route 绕开路径上的对方（避免直线穿人把球位带偏）
7. 无球角色（assist/mid/passive）目标点 position → route（P0 末接线，防范围爆炸，
   先留好接口：`motion::follow_route` 就绪后逐个角色切）

## 3. P1：自数比分 + 领先 ≥2 转防守加强

### 3.1 比分统计（平台无比分 → 自数，参考 rlg/sim_bench 越线口径）

- WorldModel 增加：`int score_us = 0, score_them = 0; bool goal_armed = false;`
  `bool lead_by_two = false; bool ball_seen_moving = false;`
- strategy.cpp 每帧 update_score（Strategy::run 第 0 步，先于局势分析）：
  - **判据 A（主，真实平台事件）**：`gameState` 从 PM_PlayOn 转换到
    `PM_PlaceKick_Yellow/Blue` → 进球后失球方开球（docs/06 L347 实测：
    "PlaceKick X = X 刚失球"）。蓝视角 PlaceKick_Yellow（黄开球）= 黄刚失球 =
    我方得分；PlaceKick_Blue = 对方得分；黄视角反之。
    前置：① `ball_seen_moving`（曾见球速 >2cm/帧——挡**开局开球**误判）；
    ② armed 未锁（上次计分后比赛已恢复）。
  - **判据 B（越线兜底）**：球越过门线且 y∈[70,110]（field_info 口径同平台）。
    真实平台若进球后球停门内若干帧可触发；sim_bench 进球瞬间重置、策略永远
    看不到越线状态（恒不可达，属预期——sim 端到端靠判据 A，见下）。
  - armed 解锁：`gameState==PM_PlayOn` 且球离开双方门区。
- **实现与方案差异（重要）**：原方案"越线锁存 + gameState 离开 PlayOn 确认"
  在真实平台不可行——进球后平台立即重置球，**球越线状态从不进入策略视野**
  （sim_bench 实证：自数恒 0）。故改为判据 A 为主。配套：sim_bench 增加
  PlaceKick 事件模拟（进球 → 失球方开球 60 帧 → PlayOn），端到端验证
  （50 场×2 seed 自数与 sim 比分逐场一致）。
- 风险标注：**半场开球误判**——若平台中场休息期间保持 PlayMode=PlayOn，
  下半场黄队开球（PlaceKick_Yellow）会被误计为我方得分（真机第一件事验证，
  必要时加"连续活球时长/半场计数"守卫）；TeamContext 固定 is_blue 的换边
  假设同前（docs/03 已有记录，rlg 全同向不换边）。
- offline_test：越线计数/锁存防重/PlaceKick 事件/开局守卫/lead 触发 12 断言全过。

- offline_test：test_score_counting（12 断言）+ test_lead_defense（决策分离）。
- 注：无事件模拟的旧 sim（进球对策略隐形）里 lead 恒 false，防守链不触发

   场景测试覆盖；仍抖 → 降频（每 3 帧重算）
3. **带球绕人丢球**：sim 的 carry 模型与真实有差距 → P0 先只对"追球/无球跑位"
   上 route，带球绕人（2.4 第 3 条）做**开关默认关**，真机验证后再开
4. **比分误计**（P1）：1 帧擦线不 armed；2 帧口径若仍误 → 3 帧
5. 每个里程碑 DLL 备份（C:\Strategy\backup_*），可一键回滚
