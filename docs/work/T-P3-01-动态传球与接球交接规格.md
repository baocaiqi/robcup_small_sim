# T-P3-01 动态传球与接球交接规格（2026-10-11）

输入：`WorldModel`、当前 `active_id`、非门将机器人编号 `1..4`；位置单位 cm，角度单位度。
输出：普通或 CoopPass 任务的 `passer_id` / `receiver_id`，以及接稳后的唯一 `ROLE_ACTIVE`。

1. 只有 `role[active_id] == ROLE_ACTIVE` 且 `active_id` 在 `1..4` 时发起传球；门将 `0` 不进入候选。接球候选是其他 `1..4` 号，普通传球保持现有评分和局部搜索，CoopPass 按候选当前角色获取站位锚点。
2. 创建和维持任务时，`passer_id` 必须是当前 ACTIVE，`receiver_id` 必须合法且不同；其余安全、准备、承诺、出球及接稳判据保持原值。
3. 生命周期顺序保持 `Preparing → Receiving → Received`。只有真实出球进入 `Receiving` 后，现有连续接稳判据才可把任务标为 `Received` 并建立临时控球。
4. `Received` 创建临时控球时置一次性 `handoff_pending`。`Strategy::run` 先取消失效任务，再分配角色并逐人计算指令；全部门区纪律执行完、临时控球仍有效时，才消费标记，把原 passer 的 ACTIVE 与 receiver 的非门将角色交换。重置候选滞回并沿用现有换人保持期；旧 ACTIVE 本帧已经停球，新 ACTIVE 下帧才执行主攻控球。
5. 交接后的临时控球归接球人，角色更新不得单独触发取消。接球人的 ACTIVE 路径继续执行原有 `carry_pass_ball` 安全控制；旧主攻退回其交换得到的角色，临时控球有效期间停车，避免双人碰球。逼抢不得覆盖持球人的指令。
6. 接球失败、对方控球、任务超时、定位球重开、门区纪律取消，或临时控球在本帧末失效时，不交接。历史任务的 passer/receiver 不一致时也不交接。
