# CoopPass 连续比赛观测报告

把配合传球看成接力赛：本轮装了只记账的计数器，发现多数任务在交棒前就撤销；同时，默认模拟器把正常运动的球速传成零，让“交棒成功”这道检查失去了可信输入。**当前证据不支持直接调整任何指定阈值。** 应先区分模拟器问题、准备动作未完成和接稳后动作退出，再在真机验证。

## 范围、样本与可复现性

- 源码起点：`60a79de`。首次构建失败：`mark_engage_threat()`、`retreat_threat()` 未定义。恢复 `60989d2` 已有的 `0.6`、`0.3` 比较值后才建立可运行基线；这是本次观测所必需的编译前置修复，不是根据比赛结果调参。最近的门将改动保留。
- 普通 `PassPlan`、传球评分、全部 CoopPass 阈值和判断顺序未改；`simuro_interface.hpp` 未改；未部署平台。还没真机验证。
- 默认输入和显式开启的 `--correct-ball-history` 补充输入各跑三种模式，每种先 **20 场**冒烟，再 **50 场**主样本；独立样本合计 **420 场**。每场完整 **24000 帧 / 600 秒**，所以不是短局或单场复制。主结论采用后面的独立 50 场；20 场仅作验收及补充。
- 冒烟基础种子 `20260921`；主样本基础种子 `20261021`。第 `g` 场从零编号，实际种子为 `(base + g * 0x9E3779B97F4A7C15) mod 2^64`，每场实际种子保存于 JSON/CSV。日志中的场号从一开始，帧号从零开始。
- 对手强度 `1.0`，未加载外部参数。默认脚本对手为我方蓝队；`yellow` 为我方黄队对脚本；`self` 两队均为当前策略。self 的配合统计分别列队，不能把两队当成独立的两场比赛。
- 修正输入只把上一帧球位保存到物理推进前，并在重摆时对齐当前和历史球位。默认路径仍保留原行为；没有修改碰撞、摩擦等物理计算。**补充输入会改变整队对球速的感知，不能把两组比分变化归因于 CoopPass。**

## 指标口径与守恒

主要结果在首次任务结束时结算且只结算一次：接稳成功、准备超时、飞行/接球超时、截球或某一取消原因。多个条件同帧成立时，按原执行顺序及安全闸门顺序记首要原因；后续取消不再累加。接稳之后临时控球退出属于另一张账，不能再次把成功任务算成失败。比赛截止仍在进行的任务记 `match_end`（未完成样本），不冒充超时或失败。

所有批次自动核验：`创建 = 所有主要结果之和`、`接稳 = success = 临时权进入 ≤ 出球 ≤ 创建`、每任务只有一个创建和一个结束事件、临时权退出总数等于进入数（含截止未完成）。接稳/出球转化率只在出球不为零时计算；0/0 写“不适用”。

原生“控球率”是近球占比，排除了双方都离球较远的时段，并不证明稳定带球。原生“射门”是球位于对方门前区域的**帧数**，不是射门脚数。下面保留这个指标并明确单位；也不把既有 `shoot_push_count` 当作射门累计总数，因为它会按回合清零。门区指标是仿真几何诊断，不会实际判罚；这里只列原生对方门区多人及单人滞留统计，**不是己方门区违规总量**。self 原生纪律列只统计蓝队。

## 逐项判断与典型失败场景

**球已传出但未确认：默认输入中证据明确。** 共 **125** 个任务出现“位移、前方位置、球人分离均达标，物理方向速度也达标，但策略方向速度为零”的候选帧。例如默认脚本主样本第 **5** 场、任务 **14**、帧 **1058**：位移 **8.96cm**、分离 **17.01cm**、物理方向速度 **4.25cm/帧**，策略速度却为 **0**。所以它仍留在准备期，根因是输入历史，不应把 `1cm/帧` 门槛降到零来迁就模拟器。

**球没有真正传出却确认：默认输入存在重摆污染的确定案例。** self 第 **1** 场蓝队任务 **172**，帧 **17572** 球在正常运动但未确认；帧 **17580** 重摆到中圈，复位编号从 **70** 变 **71**，物理球速为零，输入却产生 **1.43cm/帧** 的方向速度，因旧起点到新球位的投影达 **52.53cm** 而误确认。yellow 第 **22** 场任务 **85**、帧 **12420** 同类。两次随后都被门区纪律取消，没有变成成功接球。补充组没有复位帧出球，但有 **39/152** 次出球缺少“开启观察后传球人注入推球动量”的记录；这只是需要复核的归因疑点，不能直接宣布都是假传球，因为滚动惯性、侧碰及观察开启时机均可能解释。

**接球人碰到球但未接稳：主要观察到高速掠过，而非确认了稳定控制却漏判。** 补充组已经出球的任务中，**39** 个任务曾进入接球人 **12cm** 内，其中 **36** 个曾仍快于 **3cm/帧**。例如脚本第 **3** 场任务 **135**、帧 **17106**，接球距离 **10.99cm**、球速 **5.25cm/帧**，所以被速度门槛挡住；“进了接触范围”并不等于已经停稳。出现一帧接稳证据的任务最终都进入了接稳结果，当前样本未显示“两帧确认”造成明显漏接。模拟器没有稳定控球真值，不能据这些数据建议直接放宽接稳球速。

**接稳后给了临时权，却未形成稳定带球：存在疑点和动作失败。** yellow 第 **24** 场任务 **78**，帧 **14896–14897** 两帧距离由 **9.60cm** 降到 **5.82cm**、球速约 **2.69cm/帧**，所以接稳成立。模型记录它只是进入携带候选区，并未由接球人注入推球动量；临时权在帧 **14897** 又因带球准备点非法而立即退出。这里证明“几何接稳不保证下一步可带球”，不能进一步断言真机无球误接管。

## 阈值建议：本轮全部保留

下列“候选对照”只建议下一轮在修正输入和真机日志上离线重判或受控比较，本轮没有应用，也不是确定的新最优值。

| 当前条件 | 本轮证据与建议 |
|---|---|
| 出球位移 ≥6cm | 保留。把门槛假设降到 4cm 的静态影子检查只涉及少量准备期任务，其中多数后来本来就确认了出球；它无法解决绝大多数任务根本没开始推动的问题。可留作 4/6/8cm 灵敏度对照。 |
| 方向速度 ≥1cm/帧 | 保留，先修输入口径再评估。默认组的漏判不能用降低阈值解决。补充组可把 0.5/1cm/帧作为慢球复盘对照，但不要据当前有限样本直接降值。 |
| 球人分离 ≥14cm | 保留。12–14cm 附近存在延迟确认，但模型自身携带半径约 13.99cm；降到 12cm 可能把仍在贴身携带的球算成传出。优先真机核对 12/14/16cm 时人与球是否真的脱离。 |
| 接稳距离 <12cm | 不建议扩大。已有近球两帧后马上失效的案例，扩大范围可能更早把掠过当接稳。后续可检查 10/12cm 对照，但应同时看实际控球持续时间，而非只提高“成功计数”。 |
| 接稳速度 ≤3cm/帧 | 不建议放宽。高速近身多为掠过；现有低速成功也未保证能带球。若真机证实低速擦碰误接稳，可优先比较 2/3cm/帧；绝对球速较高但人与球同步带球的场景还需观察相对速度，不能只动一个数。 |
| 连续两帧接稳 | 当前未见它造成明显漏接，保留。若真机重复证实瞬间掠过误接管，再比较 2/3 帧确认，接受因此增加的接管延迟。 |
| 临时权距球 >20cm 连续三帧撤销 | 保留。连续远离后才撤销的实测轨迹符合设计；三例最短退出来自准备点非法，修改这组距离/帧数不解决问题。 |
| 中等威胁允许接应、高威胁 0.6 取消 | 保留。缺少因果对照；不能用整场比分变化或三次附近丢球直接判为阈值错误。 |

静态影子检查只检查已记录状态上的门槛，不重跑动作，因此**不是阈值改动后的收益预测**：补充主样本假设位移降到 4cm，会影响 **32** 个曾触及该边界的任务，其中只有 **5** 个最终从未出球；速度降到 0.5cm/帧涉及 **7** 个，其中 **6** 个最终未出球；分离降到 12cm 涉及 **35** 个，其中只有 **3** 个最终未出球。数量远小于准备阶段的总体流失，所以优先事项应是验证任务创建时机、准备动作能否完成及接稳后的安全带球动作，而不是盲目放宽门槛。

## 模拟器限制与 SimuroSot5 待验证项目

- 默认球位历史覆盖错误：正常帧策略球速为零；复位微扰可产生伪速度。本轮保留默认作为原始证据，并提供单独开启的修正输入实验。
- 始终 `PlayOn`；进球和争球直接重摆，策略对象继续存在。补充输入只消除复位速度，不主动取消跨复位任务。所有跨复位样本有编号标记；真实比赛状态取消和定位球切换仍须在 SimuroSot5 验证。
- 球的瞬时物理速度与上一帧到本帧的球位差分不同，碰墙、碰人或推出重叠体时尤其明显。日志统一换算为 cm/帧但没有把两者视为同一真值。
- “携带候选区”不是吸球或稳定持球；真正注入推球动量另记 `push_applied`。静止机器人与侧碰只能径向挡球，没有独立的“已控稳”标志，所以无法准确测出接稳误判率。
- 推球/碰撞使用移动前的指令速度，而位置运动应用加速度与延迟后的速度；突然转向、停车、倒车时可能给球不真实的动量。蓝队内部会做机器人分离，黄队内部缺少相应处理，因此 yellow 与蓝方并非严格对称实验。
- 原生门区诊断不会执行完整裁判惩罚；近球占比和门前球帧数也不等同于真机控球、射门。
- 真机应重点录制：实际推球后位移/方向速度/球人分离，接球前后身体接触与相对运动，接稳后边线及门区附近的可执行带球动作，1 号停车后的惯性干扰，中威胁接应与回防的对照，以及比赛状态/门区判罚的任务取消。**本轮没有启动或部署真机平台。**

保留已有编译警告，没有新增错误。新增测试覆盖准备/飞行超时、按原因取消、出球/接稳/临时权计数和成功后再取消不重复结算。三模式各 20 场与统计前可运行程序的逐场原生结果完全一致；后续诊断字段完善后再次比较，仍一致。独立复核发现的末场快照时间错位已修正，并在后续小样本复核；主批次的比赛指标不受该诊断字段修正影响。重复跑相同种子不增加独立样本数。

```text

python tools/py/coop_observation.py --mode scripted --history original --games 50 --seed 20261021
```

将 `scripted` 换成 `yellow`、`self` 即对应其余模式；补充组冒烟同样使用 20 场及冒烟种子。`--compare-baseline` 依赖本机保存的统计前 `build/coop_observation/sim_bench_before.exe`，普通复现无需它。对 `corrected` 的选择会显式传入 `--correct-ball-history`，默认执行不受影响。

产物位于 [coop-observation-20260921](coop-observation-20260921/)：每批 `.json` 为逐场种子、生命周期计数与原生汇总，`.diagnostics.json` 为阈值及典型帧证据，`.log` 为逐场比分/控球/门前球帧数/纪律及复位事件；本机保留压缩逐帧 `.csv.gz` 和逐任务 `.tasks.json.gz`。大体积原始轨迹仅本地保留，版本库记录汇总与复现工具；`manifest.json` 保存文件大小及 SHA-256，便于核验。`validation.json` 保存基线一致性和测试结果。
