# T-P3-03 第三人提前接应规格

输入：`WorldModel` 中当前 `CoopPassTask`、球和双方机器人坐标（cm）、角色与比赛阶段；输出：至多一名第三人的临时接应点（cm）及该机器人本帧唯一的普通移动指令。

1. 只在首段传球任务有效、比赛进行中且对方未明确控球时选点；Neutral 散球不单独取消。传球人 A、锁定接球人 B、门将和当前 ACTIVE 不可作为第三人 C。
2. 在只用于选点的 `WorldModel` 副本中，把球和 B 的位置都放到首段锁定点；逐名复用普通传球的角色锚点、局部搜索、线路净空、接球点安全及对手抢先判断，并检查 C 到目标的直线路径不被对手堵住。绝不改真实球位或预建下一段任务。
3. 用现有接球人速度、球速与准备容差估算首段剩余可用帧数：Preparing 同时考虑 B 到锁点和球到锁点，Receiving 只考虑球到锁点；均以任务 `frames_left` 封顶。局部搜索的每个候选点先检查 C 到点的移动距离和路径，不能因较远高分点而漏掉附近安全点。合格候选先比较移动距离，再比较目标进攻深度。
4. 临时接应记录首段身份、锁点和任务创建计数。相同任务且目标仍安全、可达时保留原 C 与目标；失效才重新选。首段结束或身份变化立即清空，不将锁点传给下一段。
5. `Strategy::run` 先取消失效任务、角色分配、逼抢和防守判定，再安排 C；门将、门区纪律、分区策略、接球人与传球人、逼抢/扫荡/必要盯人或回防均优先。轮到 C 派发时再次核对首段任务及身份，避免 A 在同帧创建/取消任务造成缓存误用；同帧新建任务从下帧再提前跑位。C 获得一个 `motion::position` 指令后跳过自身普通站位派发，安全兜底仍可覆盖不合规指令。
6. 明确失权、任务超时、拦截、重开球、角色不兼容或目标被封锁时清理/重新选择；Neutral 本身只使必要防守优先，不清空仍有效的首段计划。无合适 C 时立即回退原普通派发。接稳交接后 B 继续依照现有射门、带球、PassPlan 和 CoopPass 自主判断。

验收：通过 `--third-man-only` 的 `Strategy::run` 链验证两段各自 Release 与接稳、1→2→3 和 3→4→1、C 可达与原站位对照、单 ACTIVE/单任务控制、全部取消条件；Win32 MSVC Release 全目标及既有所有专项、完整 offline_test、`git diff --check` 均通过。
