# T-P3-02 交接后控制放行规格（2026-10-11）

结论：T-P3-01 的接稳交接有效，但新 ACTIVE 被 `coop_ball_control` 的持续早返回拦住，不能创建下一次 PassTask。按 T-P3-02 停止条件，本轮只修此控制权冲突与验证二次传球，不开发第三人提前接应。

输入：`WorldModel` 中已完成的首段任务、接球临时控球、当前 ACTIVE 与场上球权。
输出：接球人先按原控球路线稳住球，再恢复普通 ACTIVE 决策；下一段传球仍由原有 PassPlan/CoopPass 自主选择。

1. 首段必须先实际 Release、连续接稳且 `handoff_pending` 已在帧末消费；首段未完成时不允许下一段任务。
2. 接球人成为 ACTIVE 后，先执行一次现有 `carry_pass_ball` 控球动作；只在下一次正常派发确认仍是我方控球且人球距离满足现有控球距离时，结算临时控球。
3. 结算当帧给新 ACTIVE 停车，不创建任务；下一帧才从普通主攻路径重新比较射门、CoopPass、PassPlan。首段锁点随新任务初始化清空；新任务重新检查线路、接球人和安全取消。
4. 临时控球失效、球权变化、超时或重开球仍走既有安全取消；无合适传球时保持原射门/带球选择。
5. 同一帧始终只有一个 ACTIVE；首段旧传球人在临时控球期间不参与主攻。无需独立连续传球状态机，不修改任何数值阈值。

验收：Win32 MSVC Release 全目标、完整 offline_test、三个既有专项和新增二次传球专项、`git diff --check`；新增专项必须经 `Strategy::run` 证明 1→2 接稳后 2→3 新任务创建并执行，且未出球、失败、失权和重开不会创建第二段。
