# 规格：离线策略搜索（强化学习路线 A）— 用机器调参优化进攻与防守

> 立项目期 2026-09-15 ｜ 用户选定路线 A（离线黑箱策略搜索，非端到端神经网络）
> 关联：`docs/06-调参记录.md`（每轮结果）、`AGENTS.md`（沟通与红线约定）

## 1. 一句话目标

把策略里 **人肉定死的 ~70 个数值旋钮**交给机器搜索：仿真里跑几万局，找出在
**训练种子集**和**留出种子集**上都比现状更好的那一组，编译进 DLL，真机跑一场确认。

## 2. 为什么可行（实测依据，不是估计）

| 事实 | 实测值 | 所以呢 |
|------|--------|--------|
| 仿真速度 | 46,081 帧/秒（50 局 26 秒） | 1 小时 ≈ 7,000 局 → 够做几千次候选评估 |
| 单局耗时 | 0.52 秒 | 一次候选评估（10 局）≈ 5 秒 |
| 顶层可注入常量 | 79 个（去几何结构类后 ~70） | 参数空间够大，但必须挑，不能全塞 |
| 平台接口 | 5 个导出，40Hz，真机不能训练 | **只能离线训练 → 静态部署**（比赛时 DLL 不读文件、不联网） |

**红线遵守**：不引入第三方库（注册表头文件内联实现）；不动 `simuro_interface.hpp` 签名；
搜索出来的参数是**我们自己算出来的**，不是复制官方 demo（合规）。

## 3. 训练场与评测协议

### 3.1 对手池（防"只打得过一种脚本"）

| 对手 | sim_bench 参数 | 权重 |
|------|----------------|------|
| 脚本对手 弱 | `--opp scripted --opp-strength 0.7` | 1 |
| 脚本对手 标准 | `--opp scripted --opp-strength 1.0` | 2 |
| 脚本对手 强 | `--opp scripted --opp-strength 1.4` | 1 |
| 门线人墙 | `--opp wall` | 1 |
| 半场对称（我们守 x=0） | `--opp-mode 2` | 1 |

### 3.2 种子集切分（防过拟合仿真的关键）

- **训练集**：seed 1..40（用于搜索）
- **留出集**：seed 1001..1040（**搜索全程不可见**，只在验收时用）
- 同一候选参数在训练集上评估时，用**同一批种子**对比基线（配对比较，降方差）

### 3.3 适应度（fitness）：主目标 + 约束

```
fitness = 净胜球(均)                                  ← 主目标，越大越好
        − 0.5 × max(0, 被射门次数/场 − 基线×1.10)      ← 防守崩了要罚
        − 0.3 × max(0, 争球重置/场 − 基线×1.05)        ← 卡死/乱撞要罚
        − 1.0 × max(0, 门区2+人帧/场 − 基线)           ← 违规纪律不得变差
```
- 每一项都用**基线同种子实测值**做参照，避免"绝对阈值"拍脑袋；
- 单纯堆进攻不算赢：被射门变多、门区纪律变差都会被扣回来。

## 4. 实施步骤（每步可独立验证）

| 步 | 内容 | 验证方式 |
|----|------|---------|
| S1 | `include/simuro5/tunable.hpp` 参数注册表 + 把顶层常量改成 `TUNABLE(...)` | 默认值下 `sim_bench` 50 局结果与基线**完全一致**；`offline_test` ALL PASSED |
| S2 | `sim_bench --params <file>` / `--dump-params <file>` / 机器可读汇总行 | 注入一个已知参数（如射程 70→40）应看到射门数下降（证明注入真的生效） |
| S3 | `tools/tune/tune_es.cpp`：自研 CMA-ES（零依赖），进程内评估 | 用 2 维玩具函数验证收敛（已知最优） |
| S4 | 粗搜（低局数、大种群）→ 精搜（高局数） | 每代日志：训练集 fitness 曲线单调改善 |
| S5 | 验收：新 vs 旧 各 500 局同种子 | 训练集与**留出集**都提升；给进攻/防守分解指标 |
| S6 | 最优值写回源码常量 → 编译 DLL → 真机 1~2 场 | 真机不崩、不抖、门区纪律不退化；黑匣子数据对比 |
| S7 | 文档 + 回退参数表 | `docs/06` 轮次记录；旧参数表可一键还原 |

## 5. 验收标准（达不到就不合并）

1. **留出集**净胜球较基线 **+0.3/场 以上**（不是只看训练集）；
2. 被射门次数增幅 ≤10%，门区 2+ 人帧数不高于基线，争球重置 ≤ 基线 +5%；
3. `offline_test` ALL TESTS PASSED；`sim_bench` 默认参数行为不变；
4. 真机 ≥1 场无异常（不崩、不抖、不违规）；
5. 文档记录：搜到的参数表、旧参数表、搜索日志、留出集对比数据。

## 6. 明确不做什么（避免跑偏）

- ❌ 不在真机/比赛里在线学习（40Hz、无训练窗口、风险不可控）；
- ❌ 不做端到端神经网络（用户已选 A；若 A 收敛后仍有余量再讨论 C）；
- ❌ 不改 `Hnnu策略视频.mp4` / `Hnnu策略介绍.pdf`（交付物冻结）；
- ❌ 不引入第三方库（优化器自己写）；
- ❌ 不把"射门次数暴涨"当成进攻变好（看净胜球与被射门，不看虚指标）。

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| 过拟合仿真（真机水土不服） | 留出种子集 + 多对手池 + 真机验证；只接受留出集也提升的参数 |
| 参数互相打架（改了射程，传球阈值失配） | 分组搜索（先射门组、再传球组、最后防守组），每组评估时其余固定 |
| 搜索把策略推成"歪招"（例如全员堆前场） | 门区纪律/争球重置硬约束 + 人工 review 前 10 名候选的行为 |
| 仿真与真机物理差距 | 已用 118 场真机 .rlg 校准墙面恢复系数（0.66/0.81）；其余差距靠真机验收兜底 |
| 收益不如预期 | 允许"搜完发现没提升"——如实报告，保留旧参数，不强行合并 |
