# 第一部分 · 要求

## A 平台与合规要求（硬约束，违反即废场或取消资格）

| 编号 | 要求 | 原因 |
|---|---|---|
| R-A1 | 产物必须是 **32 位 MSVC 编译的 C++ DLL**，导出 5 个官方 mangled 名（`?RunStrategy@@YAXPAUEnvironment@@@Z` 等），文件名固定 `Strategy4Blue.dll` / `Strategy4Yellow.dll`，部署到 `C:\Strategy\` | 平台按 mangled 名加载；MinGW 符号不兼容，64 位装不进 |
| R-A2 | **`include/simuro5/simuro_interface.hpp` 的 struct 与导出签名冻结** | 改一个字节就 `LoadLibrary` 失败 → 机器人全不动 |
| R-A3 | **DLL 内禁止文件 IO**（`fopen`/写文件） | 平台是 2003 年的 Director 进程，会冻死 60~90 秒 |
| R-A4 | **不依赖外部运行时**：静态链接 `/MT`，不引入第三方库 | 赛场低配机没有 MSVC 运行库，缺 vcruntime 就加载失败 |
| R-A5 | **禁止复制官方 demo / 他人队伍代码**；可借鉴通用战术思想，但必须自研实现并在注释标注来源 | 资格审核查重（最高优先红线） |
| R-A6 | 官方 demo 源码（黄队陪练）**不得进仓库、不得进提交材料** | 同上 |
| R-A7 | 比赛运行条件：平台窗口**置顶可见**、鼠标**停在 WorldModel 窗口内** | 否则时钟停在 300、不落 `.rlg`；或开球摆位失败（CPU 停但倒计时照走） |

## P-1 判罚打断吃掉近一半比赛时间（🔴 第一优先）

**现象（最新真机场实证）**：2026-09-26 00:01 场，对手官方 demo，我方蓝位。

| 指标 | 实测 |
|---|---|
| 比分 | **黄 4 : 蓝 1**（我们输了 3 球） |
| 已进行 | ~197 秒（`Time 295 → 103`，半场 300s 未打完即中止） |
| `Penalty Kick Yellow`（**我方送点**） | **4 次** |
| `Penalty Kick Blue`（对方犯规） | 3 次 |
| `Goal Kick Blue` | 4 次 |
| `FreeBall` | 2 次 |
| 判罚总打断 | **≥13 次 / 197 秒 ≈ 4 次/分钟** |
| 实际踢球时间 | `.rlg` 2118688 B ÷ 352 B/帧 ≈ 6019 帧 ≈ **100 秒 / 197 秒 ⇒ 近 50% 被停表吃掉** |
| 该段 `Violated` 行 | **0 条** |

**关键推论**：该段**一条 `Violated` 都没有**，说明这 7 次点球**不是"推人/No pushing"**，机制未查清。

**历史量化**：`docs/20` 记录 11:29 场 `Penalty Kick Yellow` **11 次**，其中 **8 次**停表前 20 帧带"蓝侧特征"= 我方非门将在我方门区；该场「蓝队非门将在我方门区」共 **22 段 / 1755 帧**；11:52 场出现**单段 892 帧（≈22 秒）**。`docs/06` 第 68 轮（09-14 20:46 场，7444 帧）：我方门区里 ≥2 人共 **674 帧 ≈ 全场 9%**，同场被判 **9 次点球**（全部黄方主罚）。

**已做过什么 / 为什么没解决**：第 68 轮已落地硬闸 `enforce_own_goal_area()`（`src/strategy.cpp` 约 :167）——与角色无关，非门将在门区内即顶到门区前缘外 8cm（`hold_x = our_goal_x + attack_dir*58`），门将豁免。**硬闸在树里，但 09-26 仍 4 次送点。**

**待查（按可能性排序）**：
1. **调用顺序**：硬闸是否在角色函数**之前**执行 → 轮速被角色函数覆盖 ⇒ 形同虚设（最可能）；
2. **惯性过冲**：`motion::TM_PASS` 会不会把机器人又推进门区；
3. **豁免叠加**：`roles.cpp` 的"球在门区且贴球=攻门作业"、`goal_cover_point` 护门、清球/补射接管，是否绕过硬闸；
4. **判罚另有原因**：门将持球超时 / 球在门区停留超时 / 开球违规等（**未排除前不得假定病根是门区聚集**）。

**为什么这是第一优先**：用户已明确"判罚反复打断 → **无法直观观察算法优化效果**"。**在 50% 停表的噪声里做 A/B 等于白做**——不解决它，其它改动的真机效果都读不出来。

## P-2 门前无人区 → 乌龙 / 被推射（🔴）

**证据**：18 局共 26 个丢球，**23 个（88%）判定为"我方最后触球"**；球停在自家门前 `x≈216~217`（离门线 3~4cm）**停留 113 帧 = 2.8 秒无人清理**，之后滚进门；09-23 两局 5 个丢球里 4 个，门将都站在"球与自家门之间"的**场侧**、离球仅 8~10cm。历史对比：09-16 两局乌龙占比 **100%**（4/4、3/3）⇒ **此病长期存在，不是某次部署引入的**。

**根因（三条"防乌龙"规则叠加，各自都对，合起来 = 谁都不碰球）**：
1. 球在我方门区不逼抢（交给门将）；
2. 只从**球门侧**贴球，**场侧一律不追**（第 73 轮）；
3. 球贴门线 <15cm 且自己贴球 <14cm → **停轮站定、绝不碰球**（第 37 轮）。

**已做过什么**：第 74 轮加"门前清道夫"（`src/roles.cpp` `run_passive` 内，约 :1512）：球离己门 <25cm **且自己已在球门侧** → `chase_ball` 推出（从门侧推，球只会往场内走）。第 75 轮把 `gk_side_step_point` 的门槛在"球离门线 <12cm"时取 0（原 `kGkBehindMargin = 6.75991` 会放过 4.14cm 的情形，导致门将从场侧把球推进自家门，球速 +0.33→+1.33）。

**为什么可能白干 → 见 P-3。**

## P-3 门前救险绑死角色，改动根本没轮到离球最近的机器人（🔴）

**实证**：角色是**动态分配**的。黑匣子显示真机 f726 时 `b4=ASSIST / b3=PASSIVE`，而第 74 轮的"门前清道夫"写在 `run_passive` 里——当时归 b3，**b3 在 (170,141) 远离球** ⇒ **改动根本没轮到离球最近的那台机器人**。（`docs/06` 第 75 轮末尾已写明这条结论。）

**要求变更**：门前救险逻辑**不得硬绑角色**，必须按**"离球最近"**选人。

⇒ **门前行为的分支归属必须靠埋点/仿真确认，不能靠读码推断。**

## P-7 仿真/自研引擎的结论在真机反复失效（🟡 最贵的方法论问题）

| 工具 | 能回答 | **不能**回答 |
|---|---|---|
| `sim_bench`（仓库内，秒级） | 同一对手、同一档下改动 A 是否比 B 好 | 我们打得过 demo 吗（**绝对水平**） |
| `magic_rob` farm（`D:\robcup\magic_rob`，K 可达 2000/格） | 同上，样本量大得多 | 同上。**引擎比分永不对外** |

**三次翻车实证**：
1. **第 44 轮 motion**：sim 4 种子净胜 **+0.05、sd 0.66 ⇒ 噪声内**。只跑 seed1/2 时曾误判"+0.6 超噪声带"，补 seed3/4 后推翻。
2. **2026-09-09**：P0+P1 / 禁区围堵两轮 sim A/B **数字不差（±0.3 噪声内）**，真机口径**差** ⇒ 用户指令回退到历史最好版 `5eaa5b1`。
3. **第 76 轮**：引擎 19400 局配对 A/B 判"关闭传球任务更好"（控球份额 32%→56%，p≈1e−77）⇒ 真机 **黄 5 : 2 蓝**惨败，用户原话"**更加垃圾了，一点传球的策略都没，有球在前面但是没有队员上前**"，当场否决。

**加剧因素**：
- `sim_bench` 的对手强度 `--strength 2.0` 是**为对齐真实 demo 的净胜球方向/量级反推**出来的 ⇒ **是拟合，不是验证**。
- 官方 demo 的招牌战术（**5 人冲禁区 + 把球控停我方门前 (205,90) 静止 1.5~2.2 秒，追击手从 100cm 外直冲抢点推射**）**sim 根本不会做** —— 而第 44 轮、`docs/24` 针对的恰是"快攻漏防"这类 sim 对手不会做的动作。
- `sim_bench` 默认输入下 `lastBall` 被覆盖 ⇒ **策略球速恒零**，默认组的"球速"类结论无效（需 `--correct-ball-history`）。

**⇒ 结论**：sim/引擎只用来**淘汰明显更差的方案**；**"能不能上真机"必须靠官方平台的小样本 A/B**。
