# 11-sim_bench 快速仿真器使用指南

> 面向队员：B（持球进攻）、C（无球进攻）、D（防守+工程）均适用。
> 一句话：**不开比赛平台，命令行批量跑模拟比赛，快速评估策略改动效果。**

---

## 1. 这是什么 / 为什么用

sim_bench 是一个**无头（headless）快速仿真器**，直接编译我们自己的策略源码
（`src/` 下的同一份代码，与打包 DLL 完全一致），在命令行里模拟完整比赛。

| 对比项 | 真实平台 | sim_bench |
|--------|----------|-----------|
| 一场 10 分钟比赛 | 10 分钟实时 | **约 0.2 秒** |
| 100 场批量 | 不可行 | **约 20~25 秒** |
| 需要开 GUI / 加载 DLL | 需要 | 不需要 |
| 统计输出 | 需人工看日志 | 自动汇总比分/控球/射门/球位 |

**适用场景**：

- 改完任何策略代码后，快速回归：赢球/丢球有没有变化
- 复现问题：`--seed` 固定随机种子，同一场比赛可重跑
- 参数对比：改一个参数前后各跑 50 场，比平均值
- 大量样本 / 未来参数搜索的地基

**不适用场景**：

- 替代真实平台验证（脚本对手 ≠ demo，物理有简化，看相对变化不看绝对值）
- 调试平台特有行为（如 FreeBall 判罚细节、DLL 加载、帧率耦合）

## 2. 如何运行（三步）

```bat
:: ① 编译（改了 src/ 代码后都需重新编译）
cmake --build build --config Release --target sim_bench

:: ② 运行（默认 3 场 vs 脚本对手）
build\Release\sim_bench.exe --games 5

:: ③ 看输出
场01: 我们 6 : 2 对手   控球率(我们) 34%   射门 945   球位 38%/50%/11%   禁区2+人 89帧/9次
=== 汇总: 我们 61 : 21 对手 (均 6.1 : 2.1)   平均控球 34.7%   平均射门 995
=== 禁区纪律(我们): 门区2+人 均 121 帧/场, 12.9 次/场
=== 耗时 0.16s, 场均 0.16s (153567.5 帧/秒) ===
```

> 仓库根目录执行即可。`build/` 由 CMake 生成（gitignore），无需手动创建；
> 若 `build/` 尚未配置，先执行 `cmake -DBUILD_TEST=ON -B build`。

## 3. 命令行参数

| 参数 | 默认值 | 说明 | 常用示例 |
|------|--------|------|----------|
| `--games N` | 3 | 跑 N 场（每场独立随机开局） | `--games 100` 批量评估 |
| `--frames N` | 24000 | 每场帧数（24000 = 完整 10 分钟） | `--frames 6000` 快速冒烟 |
| `--opp scripted\|self\|yellow` | scripted | 脚本对手 / 自我博弈 / **我们守 x=0 打脚本（测半场对称）** | `--opp yellow` |
| `--seed N` | 时间种子 | 固定随机种子，可复现同一**组**比赛（每场独立开局，仅序列确定） | `--seed 42` |
| `--debug N` | 0 | 打印前 N 帧球/机器人逐帧状态（查 bug） | `--debug 300` |

> **--seed 说明（2026-08-26 队友修复）**：`--seed N` 时每场种子 = N + 场次×黄金比例，
> 各场独立开局，同 seed 重跑整组结果一致——适合 A/B 对比（两组用相同 seed 保证开局序列一致）。

## 4. 批量 A/B 评估（推荐流程）

改代码前后各跑一批，一键对比（`tools/py/sim_eval.py`）：

```bat
:: 改前（基线）：
python tools\py\sim_eval.py run baseline --games 50 --seed 1

:: 改代码后：
python tools\py\sim_eval.py run new --games 50 --seed 1

:: 对比：
python tools\py\sim_eval.py compare sim_eval_baseline.json sim_eval_new.json
```

输出：我们场均/对手场均/净胜球/控球率/射门/门区违规 的差异与判定（✅变好/⚠️变差/≈持平）。
**注意**：50 场均值波动约 ±0.5 球，Δ<0.5 视为噪声；重大改动建议 100 场。

> 历史背景：此前 `--seed N` 每场用同一个种子，100 场其实是同一场的拷贝，
> A/B 对比统计效力退化为单样本——已由队友修复（见 docs/06 调参记录）。

## 5. 输出指标怎么看

```
场01: 我们 6 : 2 对手   控球率(我们) 34%   射门 945   球位 38%/50%/11%   禁区2+人 89帧/9次
      └─比分      └─控球占比     └─球进对方门区帧数  └─球位分布(对方后/中/我方后) └─门区聚集(纪律)
```

| 指标 | 含义 | 怎么看 |
|------|------|--------|
| 比分 | 我们 : 对手（--opp yellow 时自动换边显示） | 主指标；校准基线约 6:2（真实最新 8:2，看相对变化） |
| 控球率 | 谁离球最近（20cm 内）的帧占比 | 改传球/跑位后看是否提升 |
| 射门 | 球进入对方门前 30cm 区的帧数 | 进攻压迫感；配合比分看转化率 |
| 球位分布 | 球在对方后场/中场/我方后场的帧占比 | 我方后场高=防线被压；对方后场高=进攻有效 |
| 禁区2+人 | 我方非门将在对方门区 2 人以上的帧数/片段 | **纪律指标**：FIRA 规则会判点球；真实我们场均被罚 1.9 个点球，sim 复现 12.9 次/场——越低越好 |

**黄金法则：同一参数下基线固定，改一处看一处，用平均值对比，不要只看单场。**

## 6. 分角色使用建议

### 改策略后必跑（所有队员）

```bat
:: 推荐用批量评估线（更严谨）：
python tools\py\sim_eval.py run baseline --games 50 --seed 1
:: 改完后再跑 new，然后 compare 对比
```

或快速冒烟：

```bat
cmake --build build --config Release --target sim_bench
build\Release\sim_bench.exe --games 30
```

改完任何 `src/` 代码后跑 30~50 场，与改动前的平均比分对比，确认没有回退。

### 查 bug / 复现问题（调试用）

```bat
:: 固定种子复现 + 看逐帧轨迹
build\Release\sim_bench.exe --games 1 --seed 42 --debug 300

f0123 球(58,91)v(-49,-7) 蓝0门(209,90) 蓝1(61,100) 蓝2(65,131) ...
      └─球位  └─球速     └─全队位置（蓝黄两行）
```

### 参数对比（调参时）

```bat
:: 改前：build\Release\sim_bench.exe --games 50 --seed 1 > before.txt
:: 改后：build\Release\sim_bench.exe --games 50 --seed 1 > after.txt
:: 对比两份汇总行
```

> 用同一个 `--seed` 序列保证两组比赛开局一致，差异只来自代码改动。

## 7. 注意事项

1. **看相对变化，不看绝对值**：仿真校准基线约 6:2（真实最新 8:2），
   单场波动大（2:0 ~ 9:4），任何结论都以"改动前后差值"为准。
2. **脚本对手 ≠ demo**：黄队为简化 AI（守门员 + 追击手 + 协防），
   不能代表真实 demo 强度；仿真通过后再上平台验证。
3. **策略代码是共享的**：改 `src/` 任意文件，sim_bench 编译的就是同一份源码，
   无需额外操作；也因此**不要在调试仿真时顺手改策略**，除非有意为之。
4. **球位分布中"蓝后场"**：指 x>147（我方守门侧），与直觉相反记得翻转看。

## 8. 常见问题

| 现象 | 处理 |
|------|------|
| 编译报错找不到 `sim_bench` 目标 | 确认构建时带 `-DBUILD_TEST=ON` |
| 每场结果完全一样 | 已修复（2026-08-27）：`--seed N` 现每场偏移种子、各场独立；历史版本固定种子才会全重复 |
| 想重跑某一场 | 记录当时的 `--seed` 与 `--games` 参数 |
| 比分异常高/低 | 先跑 30~100 场确认是趋势而非单场噪声 |
| 想看禁区纪律 | 输出末尾"禁区纪律(我们)"行：门区 2+ 人帧数/片段，越低越好（对应真实点球） |
