# 14-ua 代码导图工具使用说明

> 配套脚本（仓库 `tools/ua_dashboard/`），把 understand-anything 的产物
> `.ua/knowledge-graph.json` 变成可视化导图，并支持**一键更新到当前代码**。
> 与 `docs/work/07-ua知识图谱说明.md` 配套阅读（07 讲图谱本身，本文件讲工具怎么用）。

## 一、工具全家桶（3 个脚本 + 1 个产物）

| 文件 | 作用 | 何时跑 |
|---|---|---|
| `tools/ua_dashboard/update_ua_graph.py` | 把图谱**确定性重建**到当前代码（解析结构 + 复用旧摘要） | 代码有重要改动后，想更新图谱时 |
| `tools/ua_dashboard/build_ua_dashboard.mjs` | 读 `.ua/knowledge-graph.json` 生成**自包含交互式 HTML 导图** | 每次图谱更新后必跑 |
| `tools/ua_dashboard/serve.mjs` | 本地只读静态服务器，方便浏览器打开导图 | 想预览时 |
| `docs/work/ua-code-map.html` | 最终导图产物（数据内嵌、零依赖、可离线双击打开） | 生成器产物，勿手改 |

数据流：

```
仓库源码 ──► update_ua_graph.py ──► .ua/knowledge-graph.json ──► build_ua_dashboard.mjs ──► docs/work/ua-code-map.html
        （解析函数/依赖/行号）        （图谱本体，另镜像到            （浏览器打开）
                                      docs/work/knowledge-graph.json）
```

## 二、日常用法（3 条命令）

```bat
:: 1) 一键更新图谱到当前 HEAD（自动备份旧图谱到 .ua/*.bak-*）
python tools\ua_dashboard\update_ua_graph.py

:: 2) 重新生成导图 HTML
node tools\ua_dashboard\build_ua_dashboard.mjs

:: 3) 本地预览（保持运行，然后浏览器打开下面的地址）
node tools\ua_dashboard\serve.mjs 8754
```

浏览器访问：**http://127.0.0.1:8754/docs/work/ua-code-map.html**
（不想要服务器也行：直接双击 `docs/work/ua-code-map.html`，页面自包含可离线看）

## 三、导图能看什么（5 个标签页）

1. **🏗 分层导图**：9 个架构层纵向排布 + 文件间依赖箭头（蓝=导入、橙=跨文件调用、灰虚线=关联）。
   悬停节点高亮它的所有关联边，点击节点固定高亮并弹出详情抽屉。
2. **📁 文件依赖**：文件级 imports/calls 的清单表，可按文件名过滤，每行可点开来源/目标详情。
3. **⚙ 函数调用**：左侧选文件 → 右侧画该文件内部函数与它调用的其他文件函数（含同文件内调用箭头）。
4. **🗺 Tour 导览**：ua 生成的 13 步仓库导览，按顺序带新人走一遍项目。
5. **🔍 检索**：全局搜函数/文件/文档/配置节点，点行看摘要、标签与出入边。

## 四、更新机制说明（重要，先读再改）

本机**没有 understand-anything 工具本体**（原始分析跑在另一台 Linux 机器上），
所以更新采用与 `07` 文档一致的"**确定性重建**"思路，**不消耗 LLM token**：

- **结构真实**：文件清单 = `git ls-files`（按扩展名/忽略规则过滤，`.ua/`、`build/`、`sim_eval_*.json` 不入图）；
  函数与行号由脚本解析源码（**自动识别 UTF-16LE 编码**，roles.cpp/pass.cpp 等没问题）；
  imports 边来自 `#include` / `import` 实扫；calls 边为启发式——源函数体内出现目标函数名（词边界）。
- **摘要分层**：未改名的函数/文件/文档**复用旧图谱的人工/LLM 摘要**；新增实体用自动摘要
  （"xx：yyy 中的函数（自动更新新增）"，后续可在 `.ua/knowledge-graph.json` 里手工润色，
  再跑一次 build_ua_dashboard.mjs 即可）。
- **分层/Tour**：分层按路径规则从零重建（与原始人工分层一致、可复现）；Tour 沿用旧 13 步。
- **回滚**：每次运行先把旧图谱备份为 `.ua/knowledge-graph.json.bak-<时间戳>`；
  更新前原图谱（2026-09-07 之前）保留在 `.ua/knowledge-graph.json.bak-20260907-230346`。

### 已知边界（别当成 bug）

- 仅 `.cpp` / `.py` 提取函数节点（`.hpp` 多为声明/内联，与旧图谱语义一致，不展开）。
- calls 边是"名字出现在函数体"的启发式：注释已剥除，但字符串里的同名可能误报；
  跨文件同名的调用可能张冠李戴。改动大文件后可抽查（导图里点开函数看"出边"）。
- 摘要不是 LLM 写的，需要"给人看的高级摘要"时，可在图谱 JSON 里手工补或回原机器重跑 ua 管线。

## 五、接入团队习惯

- 新增/重命名/删除源码文件后更新图谱，产物顺带更新 `docs/work/knowledge-graph.json` 镜像
  （update 脚本不会自动同步镜像，需要时手动 `copy .ua\knowledge-graph.json docs\work\knowledge-graph.json`）。
- 想长期引用图谱的人只依赖 `docs/work/` 下的两份产物即可，不需要 `.ua/`。
- 本文件与 `docs/07` 的历史统计如有出入，以 `docs/07-ua知识图谱说明.md` 的"更新记录"为准。
