# 主动截球方案（biswas2014「传球中途拦截」思想，自研实现）

> 状态：**已实现（`kEarlyEnable` 默认关），sim 验证无触发场景，保留待真机评估**。
> 参考 biswas2014 / zjunlict2020「遍历传球轨迹、对比双方到达时间、判断中途拦截」的战术思想，
> 落到我们自己的 `defense.cpp`，不用任何第三方代码（原创红线）。

## 一句话目标

把防守从「**门神站门口等球滚过来**」升级成「**看出对方要传球，派人半路去抄**」——主动断掉对方的
进攻组织，而不是等球变成射门才反应。

## 背景：现在到底缺什么

先纠正一个误解：**「对比双方到达时间」这件事我们其实已经有了**。

看 `plan_defense`（`src/defense.cpp`）：

- `t_ball` = 球到截点的距离 ÷ 球速
- `t_me`   = 我到截点的距离 ÷ `kMySpeed`
- `t_me <= t_ball × kReachMargin` 才追，追不上就回退卡位

这段已经是「双方到达时间对比」了。**但它只对「一个点」用**——那个点是
`intercept_point` 算出来的「球轨迹 ∩ 门前 48.5cm 拦截线」这一个固定交点。

**问题就出在这**：横传 / 斜传的组织球，**根本滚不到门前那条拦截线**，于是 `intercept_point`
返回 false，`plan_defense` 直接走 else 分支，站到 `passive` 静态点上干等。结果就是对方中场
横传找接应，我们全程没反应——被动等球。

**所以呢**：我们缺的不是「算到达时间」的能力，而是把「截点」从**门前固定一条线**，扩展成
**球整条飞行轨迹上的每一个点**，逐个问「这个点我能不能比球先到」，找到最早能截住的那个点。

## 关键前提（为什么这套在我们这行得通）

- 球速阈值 `kMinBallSpeed = 1.36 cm/帧`（低于它视为停球）；
- 防守者直线速度 `kMySpeed = 2.19 cm/帧`。

**防守者比球快**。所以球一旦在飞（横传/斜传），离球最近的我方队员**大概率能先于球到达轨迹上的
某个中间点**——这就是主动截球能成立的根本原因。biswas2014 那种「毫秒级谁先到」的精密计时我们
不需要（球太慢），我们要的是「**主动判出球在飞 → 算一个中间点 → 冲过去截**」这个动作。

## 方案设计：新增 `early_intercept_point`

### 函数职责

```cpp
// 主动截球：球在飞行中（横传/斜传/横滚），沿球轨迹扫点，找「我能比球先到」的
//   最早截点。找到就站过去截，找不到返回 false（交回现有 plan_defense 兜底）。
//   —— 补现有 intercept_point 的盲区：现有只算「球到门前拦截线」，
//      横传/斜传的球根本到不了那条线，所以全程没人管。这个函数专管这些球。
bool early_intercept_point(const WorldModel &wm, int defender_id,
                           double &out_x, double &out_y);
```

### 5 步执行

1. 球得在飞（`spd >= kMinBallSpeed`），慢球/停球不抢；
2. 沿球前进方向扫采样点 `d = kEarlyStep, 2×kEarlyStep, …`（`predict_y_at_x_reflect` 已能外推）；
3. 逐个比时间：`t_ball = d/spd`、`t_me = dist(我,点)/kMySpeed`，找 `t_me <= t_ball × kReachMargin`；
4. 第一个命中的点就是最早可截点，站过去截；
5. 找不到 return false，交回现有逻辑。

### 插入位置（职责清晰，不破坏现有断门逻辑）

```cpp
if (plan.approaching && plan.ball_spd >= kMinBallSpeed &&
    intercept_point(wm, kInterceptLineDist, ix, iy)) {
    // 朝门滚的球 → 断门（现有逻辑不变）
    ...
} else if (early_intercept_point(wm, defender_id, ix, iy)) {
    // 新增：球在飞但现有逻辑不处理（横传/斜传/横滚）→ 主动中途截
    plan.target_x = ix;
    plan.target_y = iy;
} else {
    plan.target = passive;
}
```

## 三个护栏（真机踩过的坑，必须焊死）

1. **别被「滚离门口的球」牵走**（第 99 轮教训）：只截「会滚进我们危险区的球」，约束截点
   `dist_our_goal < kEarlyProtectDist`。
2. **抄不到要兜底**：第 5 步 return false → 交回现有 passive 站位。
3. **不抢「有人正持球」的球**：`opp_clear_dist < kEarlyDribbleDist`（对方贴球）→ return false，
   避免抢球推人犯规。

## 新增 TUNABLE 参数

| 参数 | 默认 | 含义 |
|------|------|------|
| `kEarlyEnable` | 0.0 | 总开关：0=关（回退旧行为），1=开 |
| `kEarlyStep` | 10.0 | 轨迹采样步长(cm) |
| `kEarlyMaxDist` | 150.0 | 采样最远距离(cm) |
| `kEarlyProtectDist` | 140.0 | 护栏1：截点离我方门的距离上限 |
| `kEarlyDribbleDist` | 20.0 | 护栏3：最近对手离球多近视为「还在带球」 |

## 风险与回退

- **最大风险**：护栏 1 没焊死 → 后卫被横传/死球牵出防区。靠 `kEarlyProtectDist` 门槛兜住。
- **回退**：单常量 `kEarlyEnable=0` 即关，`plan_defense` 行为完全回旧。零风险。

## 验证结果（2026-10-02，sim 实测，⚠️ 未上真机）

**结论先放**：代码按方案实现、编译测试全绿，但 **sim 实测无触发场景 → 无效果**。默认关（`kEarlyEnable=0`），保留待真机评估。

**实测数据**（self 对手 = 镜像我们自己，跑 1 场 ≈ 32000 次调用）：

| 球的状态 | 占比 | 说明 |
|---|---|---|
| 球速 < 1.36cm/帧（停着） | 74% | 球大部分时间不动 |
| 球在动（≥0.5cm/帧） | 26% | 最近对手 100% 离球 6~13cm（贴身带球） |

**所以呢**：球一动就有人贴身，`opp_clear`（最近对手离球距离）在球速快的帧全是 6~13cm。
「球飞到远离所有人的位置」这种**长传飞行窗口 = 0 次**，主动截球的采样循环从未命中（loop=0）。
即使放宽阈值（球速 0.3、离球 60cm）依然 0 命中。

**根因**：我们的策略（及镜像对手）是**短传带球**，球始终被球员贴着往前拱，不做长传。
5v5 小场地 + 短传打法下，「拦截飞行中的传球」没有下手机会。

**处置（用户指令"保留"）**：代码保留、默认关。`kEarlyEnable=0` 零副作用，不影响现有行为。
将来若对手换成有长传的打法，或真机官方 demo 表现出长传，可 `kEarlyEnable=1` 再试。
