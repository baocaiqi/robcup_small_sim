# 01 · 系统架构与开发指南

## 架构总览

```
┌────────────────────────────────────────────────────────┐
│  SimuroSot5.exe / WorldModel.exe (官方, 32 位, 不可改)   │
│  每周期: 构造 Environment → 调 RunStrategy → 读回轮速    │
└──────────────────────────┬─────────────────────────────┘
                           │ Environment(上帝视角全场数据)
┌──────────────────────────▼─────────────────────────────┐
│  dll_blue.cpp / dll_yellow.cpp (导出壳, ~40 行)          │
│  · 持有 TeamContext(蓝/黄)                              │
│  · 5 个导出接口 → 调核心                                 │
└──────────────────────────┬─────────────────────────────┘
                           │
┌──────────────────────────▼─────────────────────────────┐
│  Strategy::run(WorldModel&) — 每周期主循环               │
│  ┌──────────┐  ┌───────────┐  ┌───────────────────┐    │
│  │WorldModel │→│Situation   │→│RoleAssignment      │    │
│  │ 包装平台数据│  │局势+站位点 │  │效用函数分配角色     │    │
│  └──────────┘  └───────────┘  └───────────────────┘    │
│                              │                          │
│  ┌───────────────────────────▼───────────────┐          │
│  │ 角色薄壳: goalie/active/passive/assist/mid │          │
│  │ (只做"当前该调哪个模块"的 10 行判断)          │          │
│  └──────────┬────────────────┬────────────────┘          │
│             ▼                ▼                          │
│  ┌─────────────────┐  ┌──────────────┐                 │
│  │ motion(差速轮)   │  │ shoot/pass/  │                 │
│  │ Position/Chase/ │  │ defense      │                 │
│  │ Angle           │  │ (输出目标点)  │                 │
│  └─────────────────┘  └──────────────┘                 │
└─────────────────────────────────────────────────────────┘
```

**设计原则**（继承中型组）：角色文件是薄调度层，算法都在公共模块；一套代码服务所有角色。

## 每周期数据流

1. 平台调 `RunStrategy(Environment*)`
2. `world_model.update()`：把平台 struct 搬进内部结构 + 算球速/预测
3. `situation.update_stand_points()` + `analyze()`：算 3 个站位点 + 威胁等级
4. `role_assignment.assign()`：1 号固定守门，2-5 号效用函数抢 4 个角色
5. 角色薄壳调用公共模块，把目标点交给 `motion::position()`
6. 写回 `Environment->home[i].velocityLeft/Right`

## 关键设计决策（ADR）

| 决策 | 原因 |
|------|------|
| 一份核心 + 两个导出壳（不复制两份源码） | 蓝黄只差镜像参数，改一处两队生效 |
| 内核用绝对坐标 + TeamContext 参数化 | 调试直观（平台显示的就是绝对坐标），不做运行时镜像变换 |
| 行为模块输出"目标点"而非直接控制 | 与差速轮运动解耦，将来换控制算法不影响上层 |
| MSVC + 32 位（不加 extern "C"） | 平台按 mangled 名加载，见 docs/02 |
| field_info 全部 inline 到头文件 | 小函数热路径，减少编译单元耦合 |

## 开发顺序建议（从"能踢进球门"到"完整"）

1. **能跑**：构建 + offline_test 全绿（已完成 ✅）
2. **能追**：motion 参数标定（速度/转向手感）→ 单机追球
3. **能进**：active 角色直冲球门（shoot 模块调优）
4. **能守**：goalie + passive 防守（禁区规避点球）
5. **能传**：pass 模块 + assist 跑位
6. **能打**：摆位(formation) 12 态对齐规则 → 全流程演练
7. **能赢**：调参 + 日志复盘（tools/py）迭代
