# 🧩 四人分工方案 — 按数据流阶段（小型组版）

> 分工方案：按数据流阶段划分（球在谁脚下）。
>
> **核心思路（不变）**：不按"足球角色"分，按**"球在谁脚下"**这条数据流切。
> 足球场上只有两种状态：**球在我方脚下 → 决定怎么处理球**（进攻链）；**球不在我方脚下 → 去站有用的位置**（防守链）。
> 四人版把最重的进攻链再切成两半：**持球者**（球在我脚下：带球/射门）和**无球者**（球在队友脚下：传球/接应跑位）。
> 防守链 + 工程合并给第四人，全局大脑独立一人。

---

## 📊 分工总览

```
                   Strategy::run(每周期)
                          │
    ┌─────────────────────┼─────────────────────┐
    │                     │                     │
    ▼                     ▼                     ▼
 队员A（全局调度）   队员B·C（进攻链）      队员D（防守链+工程）
 "大脑：全局调度"    "球在我方脚下"        "球不在我方脚下 + 后勤"
                          │
                 ┌────────┴────────┐
                 ▼                 ▼
            队员B（持球）      队员C（无球）
          带球/推进/射门      传球/接应/跑位

 world_model 包装     B: motion(差速轮)      D: roles: goalie / passive
 situation 局势+站位   B: shoot(射门)         D: defense(区域防守)
 role_assignment 分配  B: roles: active       D: field_info(场地工具)
 strategy 主调度       B: geometry(几何)      D: tools/py(日志/调参)
 formation 摆位12态    C: pass(传球)          D: CMakeLists(构建)
 DLL 集成(蓝/黄)       C: roles: assist/midfield
                       C: 接应点/跑位智能（与 A 的站位点联动）
```

**四人的数据流职责（一句话）**：

| 队员 | 管什么 | 核心问题 |
|------|--------|---------|
| A | 全局：**谁该干什么** + 比赛流程 | 5 个机器人分别扮演什么角色？现在是什么比赛状态？ |
| B | 持球进攻：**球在我脚下时自己怎么处理** | 射门还是带球推进？怎么平稳走过去？ |
| C | 无球进攻：**球在队友脚下时我站哪、传给谁** | 传给谁最稳？接应点在哪？路线被不被挡？ |
| D | 防守 + 工程：**球不在我方脚下时站哪** + 后勤 | 守门员怎么守？其他人怎么拦截/补位？测试怎么跑？ |

## 队员 A：全局调度 + 世界模型 + 摆位

**一句话**：你是大脑。把平台给的上帝视角数据整理成一张清晰的"场上局势图"，决定 5 个机器人分别当什么角色，算好每个人的站位参考点，管好 12 种比赛状态的切换和摆位。

### 负责的文件

| 文件 | 干什么 | 现状 |
|------|--------|------|
| `world_model.hpp/cpp` | Environment → 内部结构（球三帧/队友/对手/球权） | ✅ 已实现 |
| `situation.hpp/cpp` | 局势分析（球权/威胁等级）+ 3 个站位参考点（防守/助攻/中场） | ✅ 已实现（待调参） |
| `role_assignment.hpp/cpp` | 效用函数给 2-5 号分配角色（1 号固定守门） | ✅ 已实现 |
| `strategy.hpp/cpp` | 每周期主调度：站位→分析→分配→角色执行 | ✅ 已实现 |
| `formation.hpp/cpp` | 12 种 PlayMode 摆位（先摆/后摆/门球球位） | ✅ 已实现（需实测校准） |
| `dll_blue.cpp` / `dll_yellow.cpp` | 5 个导出接口壳 + 队名 + 写回轮速 | ✅ 已实现 |
| `simuro_interface.hpp` | 官方接口定义（**禁改**） | ✅ 已实现 |

### 核心逻辑（你要懂的）

```
每周期 (RunStrategy 被平台调用)：
1. wm.update(env)            // 搬运数据
2. sit_.update_stand_points()  // 防守点/助攻点/中场点（B/C/D 都吃这 3 个点）
3. sit_.analyze()              // 球权 + 威胁等级
4. ra_.assign(wm)              // 1号守门, 2-5号抢 4 角色
5. 按 role[i] 调 run_goalie/run_active/...（薄壳在 roles.cpp，你和 B/C/D 共用）
6. 写回 velocityLeft/Right
```

### 需要的技术

- C++ 结构体/数组、简单的类组合（不需要 ROS2）
- 贪心分配算法（role_assignment 里已移植好，理解即可）
- 状态机思维：12 种 PlayMode ↔ 摆位模板的对应（formation.cpp）
- 平台兼容性知识（32 位/MSVC/mangled 名，见 docs/02）

### 典型工作

- 调 `role_assignment` 的惯性系数（-8）和角色顺序，解决"追球角色抖动"
- 校准 `formation.cpp` 12 态摆位（对照 docs/00 规则，实测争球/点球站位）
- 联调：B 改 motion 手感、C 改传球、D 改守门逻辑后，你负责跑 offline_test + 复盘
- 维护 `SetXXXTeamName` 队名（部署执行见本地文档）

### 最难的点

**角色切换抖动**（球在场地中央双方都够得着时，ACTIVE 角色在两台机器人之间反复横跳）——需要滞后/惯性机制，你已经有了（-8 惯性），调好阈值就行。

## 队员 B：持球进攻（带球 + 射门）

**一句话**：我不关心全局调度。A 告诉我"你是 ACTIVE"，我负责：球在我脚下时决定**射门还是带球推进**，并且让机器人**平稳走过去**——不转圈、不撞人、追上球。传球决策我调用 C 的模块，我只管"什么时候该传"。

### 负责的文件

| 文件 | 干什么 | 现状 |
|------|--------|------|
| `motion.hpp/cpp` | 差速轮控制：angle / position / chase_ball / stop | ✅ 已实现（官方算法基底） |
| `shoot.hpp/cpp` | 射门决策：时机判断 + 瞄门柱开口 + 避开守门员 | ✅ 已实现（待调参） |
| `roles.cpp`（run_active） | 持球角色薄壳：射门 → 传球 → 追球 的决策顺序 | ✅ 已实现 |
| `geometry.hpp/cpp` | 角度归一化/点线距离（你和 C 天天用，由你维护） | ✅ 已实现 |

### 核心逻辑（你要懂的）

```
run_active（球在脚下，A 分配你为 ACTIVE）：
1. plan_shoot()  能射门？→ 冲球门开口（目标点=球后方8cm推球点）
2. plan_pass()   不能射？→ 调用 C 的模块，传给位置最好的队友（接口已稳定，C 管内部实现）
3. chase_ball()  都不行？→ 追预测球位（带减速防冲过头）

motion::position() 是核心：
  desired_angle = atan2(目标-自己)   → 角度差 theta_e
  drive = vc*(sigmoid(距离)-0.3)     → 近慢远快
  vl = drive - Ka*theta_e; vr = drive + Ka*theta_e
```

### 需要的技术

- 数学：atan2、向量、sigmoid、P 控制（Kp 调参）
- 少量足球理解：射门角度、带球路线
- **几乎不涉及平台/规则细节，纯算法向**——最适合喜欢数学的人

### 典型工作

- 调 `motion` 参数（vc、Ka 分段表、到位阈值）——"机器人转圈/过头"都是你的问题
- 调 `shoot` 阈值（射门距离 70cm、开口余量 4cm）——"射门老打守门员身上"是你的问题
- 和 C 约定传球接口：run_active 里"什么时候调 plan_pass"归你，"传给谁/怎么避开挡"归 C
- 每轮联调：追球 → 带球 → 射门，逐步加复杂度

### 最难的点

**差速轮控制手感**——差速轮只能"转向+前进"，到点会有 overshoot 和抖动。官方 Position() 的 sigmoid 已经不错，但 Ka 表要按实际平台手感调。

## 队员 C：无球进攻（传球 + 接应跑位）

**一句话**：我不持球。A 告诉我"你是 ASSIST/MIDFIELD"、告诉我站位点，我负责：**站好接应位**（给持球的 B 出球点），以及 **plan_pass 的传球决策**——传给谁最稳、路线有没有被挡。B 的 run_active 会调用我写的传球模块。

### 负责的文件

| 文件 | 干什么 | 现状 |
|------|--------|------|
| `pass.hpp/cpp` | 传球决策：选接应队友 + 路线被挡检测 | ✅ 已实现（简化版） |
| `roles.cpp`（run_assist/run_midfield） | 无球跑位薄壳：站 A 算好的助攻点/中场点 | ✅ 已实现 |
| 接应点智能 | 把"接应点=队友位置前 5cm"升级为动态前移/拉开 | 🚧 待做（第一轮后） |

### 核心逻辑（你要懂的）

```
run_assist / run_midfield（球在队友脚下，A 分配你为 ASSIST/MIDFIELD）：
→ 站 A 算好的 assist_pt / mid_pt（无球跑位，给持球人出球点）
   ——站位点由 A 的 situation.cpp 维护，你的职责是"怎么站得更聪明"（前移/拉开/躲防守人）

plan_pass（被 B 的 run_active 调用）：
1. 选接应者：除持球者外离对方球门最近的队友
2. 接应点 = 队友位置朝球门方向前移 5cm
3. 路线被挡（对手距传球线 <15cm）或太远（>60cm）→ 返回"不传"
```

### 需要的技术

- 数学：点线距离（`point_to_segment_dist`）、向量
- 足球理解：传球路线、接应时机、拉开空间
- **接口协作**：你的 `plan_pass` 被 B 的 run_active 调用，你的站位点由 A 提供——你处在接口中间，沟通要勤

### 典型工作

- 调 `pass` 的挡路阈值（15cm）和最大传球距离（60cm）——"传球老被断"是你的问题
- 给 `pass` 加"接应点稍微前移"的智能（现在接应点=队友位置前 5cm，太死板）
- 和 A 联调站位点：assist/midfield 点要和 B 的带球路线错开，别站一条直线上
- 每轮联调：2 过 1（B 带球 → 传你 → 你射门），逐步加复杂度

### 最难的点

**传球时机的把握**——传太早队友没到位、传太晚路线被挡。现在逻辑是"离球门最近的队友就传"，缺"等一等/换人传"的智能，这是第一轮之后精进的方向。

### 核心逻辑（你要懂的）

```
run_goalie（1号）：
  球在我方半场 → 站球门前 10cm，y 跟球（夹 [76,104]）

Python 复盘：
  python tools\py\rlg_analyzer.py 比赛.rlg --frame N  看单帧
  python tools\py\rlg_analyzer.py 比赛.rlg --csv out.csv  看全场轨迹
```

### 需要的技术

- 数学：线性插值（拦截点计算）
- Python：struct 二进制解析（.rlg 已写好）、CSV、简单统计
- 构建：CMake/MSVC 命令行（编译、报错排查）
- 规则知识：门区/罚球区/点球判罚（docs/00）——你负责守住"不送点球"

### 典型工作

- 调守门员参数（门前距离 10cm、出击距离 18cm/45cm）
- 用 rlg_analyzer 复盘比赛，找出"丢球瞬间"（球怎么进的、守门员站位问题）
- 维护 offline_test：B/C/A 每加一个函数，你帮加一条测试用例
- 维护调参记录：每轮联调后把全队改过的参数归档

### 最难的点

**判断"要不要出击"**——出击太早被过、太晚扑不到。需要看球速（ball.vx/vy，你已经在 world_model 里有了）做预判，这是第一轮之后精进的方向。
