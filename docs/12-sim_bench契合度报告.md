# sim_bench 契合度报告（2026-08-26，2026-08-29 勘误）

> 目的：回答"sim_bench 仿真结果与真实平台是否可靠一致、能否用于策略排序"
> 方法：真实平台官方 log（权威）vs sim 批量统计 + 物理参数反推校准 + 盲测验证

---

## 0. ⚠️ 勘误声明（2026-08-29，重要）

本报告原结论基于对官方 SimuroSot5.log 的**误读**：log 比分格式实测为 **(黄 : 蓝)**
（首位=黄队），原记录"7:2 我们赢"实为 **8:2 demo(黄) 赢我们(蓝)**（rlg 物理越线逐球核对
8 破蓝门 + 2 破黄门）。**真实基线 = demo 3.5 : 我们 0.8（2 胜 1 平 11 负），我们打不过 demo。**
sim 的"我们赢脚本对手 6:1"是脚本对手强度不足的假象 → **sim 只能做相对 A/B，不能代表真实绝对水平**。
详细勘误与数据见 docs/06（2026-08-24/26 校准轮次）。

---

## 1. 结论（TL;DR，勘误后）

**⚠️ C 级：sim 可用于相对 A/B 排序（同一策略改动前后比均值），绝对比分与真实方向相反、量级不符。**

| 判定项 | 结果（勘误后） |
|--------|------|
| ① 方向一致（真实 demo 赢我们 ↔ sim 我们赢脚本） | ❌ **相反** → **2026-08-30 已修正**：脚本对手加 `--strength` 档位，2.0 档 sim = 我们 2.9:5.4（净 -2.5），与真实（净 -2.7）**方向一致**（见 §7） |
| ② 量级一致 | ❌ 我们进球 sim 6.1 vs 真实 0.8~2；失球 sim 1.8 vs 真实 3.5~8（新档失球 5.4 已对齐量级，我方进球仍虚高） |
| ③ 相对 A/B（改参数前后比） | ✅ 有效（同一对手同种子可比） |

## 2. 校准做了什么（3 轮）

### 物理参数反推（tools/py/sim_calib.py，16+ 场真实 rlg 运动学）

| 参数 | 真实实测 | sim 校准值 | 说明 |
|------|---------|-----------|------|
| 球衰减 kBallDecay | 0.986~0.994/帧（高速段） | 0.985 | ✅ 一致（低速段 rlg 量化恒定，不可采样） |
| 撞墙反弹 kWallRest | x=0.458 / y=0.449 | 0.45 | 校准 |
| 撞墙平行摩擦 kWallFric | （新增） | 0.90 | 修复"球沿墙滑进球门"失真（2007 论文怪癖: 球卡四角） |
| 机器人加速度 | p95≈336 cm/s² | 300 | ✅ 一致 |
| demo 门将横向速度 | p90≈47cm/s | 30cm/s+0.3s延迟 | 峰值 47 但失误多（见下） |

### 行为根因修复（3 个导致比分失真的问题）

1. **球贴墙滑动不减速** → 撞墙平行分量也衰减（kWallFric）
2. **脚本追击手带球太完美** → 推球点 ±14cm 抖动 + 近球减速（真实 demo 场均才 0.8 球）
3. **脚本门将跟球 100% 贴脸** → 真实 demo 门将 p50 差 6.4cm、25% 时间失位；限速降至 30cm/s + 0.3s 延迟

### 校准过程比分演化

| 阶段 | sim 比分 | 对照真实 |
|------|---------|---------|
| 校准前 | 7.2 : 3.2 | 方向对但失球虚高 |
| 修复墙摩擦 | 4.2 : 2.5 | 失球降 |
| 修复追击手 | 4.0 : 1.8 | 控球 25→34% |
| 修复站位避球 | 3.0 : 1.4 | 失球合理 |
| 修复门将（终版） | **6.1 : 2.1**（100场） | ~~真实最新 7:2~~ → 勘误：demo 8 : 我们 2（log (黄:蓝)） |

## 3. 盲测验证（勘误后）

用户 2026-08-26 跑真实平台（最新 DLL）vs demo，官方 SimuroSot5.log 场20 终场 (8:2) =
**demo(黄) 8 : 我们(蓝) 2，我们输**（原记录"7:2 我们赢"为 log 格式误读）。

sim 100 场 = **6.1 : 2.1（我们赢）** → 与真实（我们输）**方向相反、量级不符**，**不通过**。
根因：脚本对手强度 << demo（demo 带球推进/射门/门将表现都强于脚本模型），
且我方进攻被 sim 高估（sim 6.1 球 vs 真实 0.8~2 球）。

## 4. 使用边界（重要）

### ✅ 可以放心用
- **策略排序 / A/B 对比**：改参数前后各跑 30-50 场比均值，结论与真实一致
- **回归测试**：防策略回退（--seed 可复现）
- **快速筛选**：大量想法先在 sim 过滤，再上真实平台验证

### ⚠️ 需要注意
- **绝对比分有 ±1 球波动**：6.1:2.1 是 100 场均值，单场范围大（2:0 ~ 9:4）
- **控球率口径**：sim 34.5% vs 真实 rlg 统计 42%——但 rlg 本身不可靠（不完整+字段问题），
  此项未最终确认；如需精确对齐需平台完整 rlg
- **脚本对手 ≠ demo**：黄队是简化 AI（守门员+追击手+协防+站位），行为已对齐比分量级，
  但不复现 demo 的每个细节（如禁区犯规频率、点球次数）
- **使用前重跑校准**：若策略大改（如新增模块改变攻防节奏），建议重跑 sim_verify 确认未漂移

### ❌ 不可用
- 把 sim 比分当真实成绩汇报（如"我们 sim 6:2，平台也是"——需平台验证）
- 精确预测禁区判罚/点球数（sim 未建模犯规判罚链）

## 5. 残余偏差与后续

| 偏差 | 现状 | 影响 |
|------|------|------|
| 失球 2.1 vs 真实 2 | ±0.1 | 可忽略 |
| 进球 6.1 vs 真实 7 | ±0.9 | 可接受 |
| 控球率口径 | sim 34.5% vs rlg 42%（rlg 不可靠） | 待完整 rlg 确认 |
| 脚本对手细节 | 不建模犯规/点球 | 影响绝对判罚预测 |

**后续建议**：
1. 若需控球率精确对齐：平台确认 rlg 完整录制设置后重采
2. 每次重大策略改版后重跑 sim_verify（1 分钟）防校准漂移
3. 校准脚本与工具已入库：`tools/py/sim_calib.py`、`tools/py/sim_verify.py`、`tools/sim_bench/`

## 7. 脚本对手强度标定档（2026-08-30，sim 方向修正）

勘误后真实基线 = **demo 3.5 : 我们 0.8（净 -2.7，我们输）**，而旧脚本档 sim = 我们 6.1:2.1（净 +3.3，方向相反）。
本轮给脚本对手加 `--strength` 强度倍率（门将横向速度×S、反应间隔 12/S 帧、追击手抖动 14/S cm、近球减速 30+25(S-1)、远球 80×(0.6+0.4S)），
按 30 场 seed 1 标定扫描：

| strength | sim 比分（我们:脚本） | 净胜 | 说明 |
|----------|----------------------|------|------|
| 1.0（旧档） | 4.7 : 1.4 | +3.3 | 方向与真实相反 |
| 1.5 | 3.5 : 3.4 | +0.1 | 五五开 |
| **2.0（选定）** | **2.9 : 5.4** | **-2.5** | **对齐真实 -2.7 的方向与失球量级** |
| 2.5 | 1.8 : 6.8 | -5.0 | 过强 |
| 3.0 | 2.1 : 9.1 | -7.0 | 过强 |

**结论**：sim_eval 默认 `--strength 2.0`（sim_eval.py run 已内置），sim 绝对比分方向与真实一致
（我们弱于脚本/demo）。**残余偏差**：sim 我方进球仍虚高（2.9 vs 真实 0.8）——sim 不建模
真实平台的我方带球失误/射门偏出/点球执行，标定只能对齐方向与失球量级，不能对齐我们进球。
A/B 对比规则不变：同档位同种子比均值。
