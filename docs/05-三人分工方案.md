# 🧩 三人分工方案 — 按数据流阶段（小型组版）

> 分工方案：按数据流阶段划分（球在谁脚下）。
>
> **核心思路（不变）**：不按"足球角色"分，按**"球在谁脚下"**这条数据流切。
> 足球场上只有两种状态：**球在我方脚下 → 决定怎么处理球**（进攻链）；**球不在我方脚下 → 去站有用的位置**（防守链）。两条决策链分开给不同队员，第三条给"与球权无关的全局大脑 + 工程"。

---

## 📊 分工总览

```
                   Strategy::run(每周期)
                          │
    ┌─────────────────────┼─────────────────────┐
    │                     │                     │
    ▼                     ▼                     ▼
 队员A（组长）        队员B（进攻链）       队员C（防守链+工程）
 "大脑：全局调度"     "球在我方脚下"        "球不在我方脚下 + 后勤"

 world_model 包装     motion(差速轮)        roles: goalie / passive
 situation 局势+站位   shoot(射门)          defense(区域防守)
 role_assignment 分配  pass(传球)          field_info(场地工具)
 strategy 主调度       roles: active/       tools/py(日志/调参)
 formation 摆位12态    assist/midfield      CMakeLists(构建)
 DLL 集成(蓝/黄)        → 追球/带球/推进       → 站位/拦截/守门
```

**三人的数据流职责（一句话）**：

| 队员 | 管什么 | 核心问题 |
|------|--------|---------|
| A | 全局：**谁该干什么** + 比赛流程 | 5 个机器人分别扮演什么角色？现在是什么比赛状态？ |
| B | 进攻：**球在我方脚下时干什么** | 射门还是传球还是带球推进？怎么走过去？ |
| C | 防守：**球不在我方脚下时站哪** + 工程 | 守门员怎么守？其他人怎么拦截/补位？测试怎么跑？ |

## 队员 A（组长）：全局调度 + 世界模型 + 摆位

**一句话**：你是大脑。把平台给的上帝视角数据整理成一张清晰的"场上局势图"，决定 5 个机器人分别当什么角色，算好每个人的站位参考点，管好 12 种比赛状态的切换和摆位。

### 负责的文件

| 文件 | 干什么 | 现状 |
|------|--------|------|
| `world_model.hpp/cpp` | Environment → 内部结构（球三帧/队友/对手/球权） | ✅ 已实现 |
| `situation.hpp/cpp` | 局势分析（球权/威胁等级）+ 3 个站位参考点 | ✅ 已实现（待调参） |
| `role_assignment.hpp/cpp` | 效用函数给 2-5 号分配角色（1 号固定守门） | ✅ 已实现 |
| `strategy.hpp/cpp` | 每周期主调度：站位→分析→分配→角色执行 | ✅ 已实现 |
| `formation.hpp/cpp` | 12 种 PlayMode 摆位（先摆/后摆/门球球位） | ✅ 已实现（需实测校准） |
| `dll_blue.cpp` / `dll_yellow.cpp` | 5 个导出接口壳 + 队名 + 写回轮速 | ✅ 已实现 |
| `simuro_interface.hpp` | 官方接口定义（**禁改**） | ✅ 已实现 |

### 核心逻辑（你要懂的）

```
每周期 (RunStrategy 被平台调用)：
1. wm.update(env)            // 搬运数据
2. sit_.update_stand_points()  // 防守点/助攻点/中场点
3. sit_.analyze()              // 球权 + 威胁等级
4. ra_.assign(wm)              // 1号守门, 2-5号抢 4 角色
5. 按 role[i] 调 run_goalie/run_active/...（薄壳在 roles.cpp，你和 B/C 共用）
6. 写回 velocityLeft/Right
```

### 需要的技术

- C++ 结构体/数组、简单的类组合（不需要 ROS2）
- 贪心分配算法（role_assignment 里已移植好，理解即可）
- 状态机思维：12 种 PlayMode ↔ 摆位模板的对应（formation.cpp）
- 平台兼容性知识（32 位/MSVC/mangled 名，见 docs/02）——**全队只有你懂，比赛当天你负责部署**

### 典型工作

- 调 `role_assignment` 的惯性系数（-8）和角色顺序，解决"追球角色抖动"
- 校准 `formation.cpp` 12 态摆位（对照 docs/00 规则，实测争球/点球站位）
- 联调：B 改 motion 手感、C 改守门逻辑后，你负责跑 offline_test + 复盘
- 改 `SetXXXTeamName` 队名；比赛日部署 DLL 到 C:\Strategy

### 最难的点

**角色切换抖动**（球在场地中央双方都够得着时，ACTIVE 角色在两台机器人之间反复横跳）——需要滞后/惯性机制，你已经有了（-8 惯性），调好阈值就行。

## 队员 B：进攻链（球在我方脚下）

**一句话**：我不关心全局调度。A 告诉我"你是 ACTIVE/ASSIST/MIDFIELD"，我负责：球在我脚下时决定**射门还是传球还是带球**，并且让机器人**平稳走过去**——不转圈、不撞人、追上球。

### 负责的文件

| 文件 | 干什么 | 现状 |
|------|--------|------|
| `motion.hpp/cpp` | 差速轮控制：angle / position / chase_ball / stop | ✅ 已实现（官方算法基底） |
| `shoot.hpp/cpp` | 射门决策：时机判断 + 瞄门柱开口 + 避开守门员 | ✅ 已实现（待调参） |
| `pass.hpp/cpp` | 传球决策：选接应队友 + 路线被挡检测 | ✅ 已实现（简化版） |
| `roles.cpp`（run_active/run_assist/run_midfield） | 持球角色薄壳 | ✅ 已实现 |
| `geometry.hpp/cpp` | 角度归一化/点线距离（你天天用） | ✅ 已实现 |

### 核心逻辑（你要懂的）

```
run_active（球在脚下，A 分配你为 ACTIVE）：
1. plan_shoot()  能射门？→ 冲球门开口（目标点=球后方8cm推球点）
2. plan_pass()   不能射？→ 传给位置最好的队友（路线无对手挡住）
3. chase_ball()  都不行？→ 追预测球位（带减速防冲过头）

run_assist / run_midfield（球不在你脚下但属于进攻方）：
→ 站 A 算好的 assist_pt / mid_pt（无球跑位，给持球人出球点）

motion::position() 是核心：
  desired_angle = atan2(目标-自己)   → 角度差 theta_e
  drive = vc*(sigmoid(距离)-0.3)     → 近慢远快
  vl = drive - Ka*theta_e; vr = drive + Ka*theta_e
```

### 需要的技术

- 数学：atan2、向量、sigmoid、P 控制（Kp 调参）
- 少量足球理解：射门角度、传球路线
- **几乎不涉及平台/规则细节，纯算法向**——最适合喜欢数学的人

### 典型工作

- 调 `motion` 参数（vc、Ka 分段表、到位阈值）——"机器人转圈/过头"都是你的问题
- 调 `shoot` 阈值（射门距离 70cm、开口余量 4cm）——"射门老打守门员身上"是你的问题
- 给 `pass` 加"接应点稍微前移"的智能（现在接应点=队友位置前 5cm）
- 每轮联调：追球 → 射门 → 传球，逐步加复杂度

### 最难的点

**差速轮控制手感**——差速轮只能"转向+前进"，到点会有 overshoot 和抖动。官方 Position() 的 sigmoid 已经不错，但 Ka 表要按实际平台手感调。

## 队员 C：防守链 + 系统集成

**一句话**：最后一道防线 + 全队后勤。守门员归我，区域防守归我，Python 复盘工具归我，构建/调参/比赛部署归我。

### 负责的文件

| 文件 | 干什么 | 现状 |
|------|--------|------|
| `roles.cpp`（run_goalie/run_passive） | 守门员 + 防守站位薄壳 | ✅ 已实现 |
| `defense.hpp/cpp` | 区域防守：拦截点（球-门连线 50cm） | ✅ 已实现 |
| `field_info.hpp` | 场地常量/门区/罚球区/进球判断 | ✅ 已实现 |
| `tools/py/*.py` | .rlg 日志解析/复盘/调参辅助 | ✅ 已实现 |
| `CMakeLists.txt` | 构建维护（B 加文件你要更新 CORE_SOURCES） | ✅ 已实现 |
| `offline_test.cpp` | 冒烟测试维护（每次新功能加用例） | ✅ 已实现 |
| `docs/06-调参记录.md` | 全队调参记录（你维护） | ✅ 已实现 |

### 核心逻辑（你要懂的）

```
run_goalie（1号）：
  球在我方半场 → 站球门前 10cm，y 跟球（夹 [76,104]）
  球逼到门前(<18cm 且距门<45cm) → 出击扑球
  规则红线：门区只有守门员能进；禁区内不能久留（会送点球）

run_passive（防守站位）：
  站 A 算的 passive_pt（球-门连线、距门 50cm）
  不进球门区、不越罚球区

Python 复盘：
  python tools\py\rlg_analyzer.py 比赛.rlg --frame N  看单帧
  python tools\py\rlg_analyzer.py 比赛.rlg --csv out.csv  看全场轨迹
```

### 需要的技术

- 数学：线性插值（拦截点计算）
- Python：struct 二进制解析（.rlg 已写好）、CSV、简单统计
- 构建：CMake/MSVC 命令行（编译、报错排查）
- 规则知识：门区/罚球区/点球判罚（docs/00）——你负责守住"不送点球"

### 典型工作

- 调守门员参数（门前距离 10cm、出击距离 18cm/45cm）
- 用 rlg_analyzer 复盘比赛，找出"丢球瞬间"（球怎么进的、守门员站位问题）
- 维护 offline_test：B/A 每加一个函数，你帮加一条测试用例
- 维护调参记录：每轮联调后把全队改过的参数归档

### 最难的点

**判断"要不要出击"**——出击太早被过、太晚扑不到。需要看球速（ball.vx/vy，你已经在 world_model 里有了）做预判，这是第一轮之后精进的方向。

## 开发顺序（1 个月，4 轮）

```

  C: 守门员跟球不出门柱 + rlg_analyzer 复盘官方 demo 日志

第二轮 联调收敛
  A: 主调度链全通（站位→分配→角色执行）

第三轮 比赛流程
  A: 12 态摆位对齐规则（点球/门球/争球实测）
  B: 传球+助攻跑位
  C: 守门员出击预判（用球速）
  总验收: 和 demo 打满 5 分钟，不失分或被罚点球

第四轮 调参 + 复盘迭代
  A: 攻防平衡（威胁等级偏置）
  B: 射门力度/角度自适应
  C: 参数归档 + 资格材料
  总验收: 复盘日志找到 2 个可改进点并落地
```

### 卡住怎么办（照着做，别硬扛）

```
motion 转圈/不过去 → vl=100, vr=100 先直走；再调 Ka 表
shoot 不进     → 去掉开口选择，硬编码瞄球门中心
pass 传不准    → 先不传，只带球射门
守门员乱跑     → 站死 (门前10, 90) 不动
摆位越界       → 检查 formation 的 clamp；对照 docs/00 规则
DLL 加载失败   → 找 A（32位/MSVC/路径三件套检查）
```
