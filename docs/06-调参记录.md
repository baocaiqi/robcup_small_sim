- **2026‑08‑21（pass模块，第1轮逻辑迭代）**
  - **pass 接应点计算逻辑升级**：从「直接使用队友本体坐标做距离校验」改为**以队友动态向前偏移后的接应点(rx2,ry2)作为判断基准**。
    - 根据接应点周边敌方威胁数量动态计算偏移量：`dynamic_offset = OFFSET_BASE * max(0.2, 1.0‑0.25*threat)`；威胁越高，向前偏移越小。
    - 距离过滤（8‑60 cm）、线路阻挡检测均作用于偏移后的接应点，而非队友原始位置。
  - **传球目标打分逻辑重构**：`score = 到对方球门距离 + 威胁数量 × 12.0`，score最小者选为最佳传球目标；兼顾靠近对方球门与敌方威胁。
  - **过滤条件**：①偏移后接应点落在[8,60]cm区间；②传球线段不被敌方机器人阻挡；满足两项才进入候选。
  - **离线测试说明**：原有`offline_test.cpp`受局部变量内存残留污染会出现误FAIL，不修改该Git管理文件；新增独立清零式本地测试用例用于验证pass逻辑，不纳入仓库提交。
  - 参数暂未实机仿真，待后续仿真跑通后，根据传球成功率、漏选候选、阻挡误判场景再微调阈值与威胁权重。
- **2026‑08‑21（defense模块，增加可达性判断）**
  - 断球点算出后加「我赶不赶得上」——
    我到点时间 = dist(我,截点)/kMySpeed，球到点时间 = dist(球,截点)/球速，
    我 > 球×1.2 就回退卡位，避免追够不着的球而失位（kMySpeed 需 rlg 复盘标定）。
