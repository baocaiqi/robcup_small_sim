# 13-禁区纪律修改建议（给 C/D 队员）

> 背景：真实比赛我们**场均被罚 1.9 个点球**（官方 log 16 场累计 30 次，最多一场 6 次）。
> sim_bench 已复现并量化此问题：**对方门区 2+ 人违规 12.9 次/场、121 帧/场（3 秒）**。
> 每个点球 ≈ 送对方 0.5~1 球机会，是当前最大的失分漏洞之一。
>
> 数据来源：sim_bench 禁区纪律统计 + 官方 SimuroSot5.log 点球记录交叉验证（2026-08-26）。

---

## 1. 根因（sim 逐帧定位，见 docs/06 调参记录 2026-08-26 条目）

球被推进到对方门前（x<50）时，我方两台非门将机器人跟着压进对方门区：

| 机器人 | 角色 | 行为 | 根因代码 |
|--------|------|------|---------|
| 蓝4 | PASSIVE | 从中场跟着球冲向门区 | `run_passive` 人盯人分支：mark_target 盯的对方防守球员就在其自家门区附近，跟着盯进去（`roles.cpp`）；盯人站位虽有 `in_penalty_area` 约束但**只保护己方罚球区** |
| 蓝2 | MID | 助攻站位随球前移 | `run_midfield` 进攻站位（`situation.cpp` 的 assist/mid 锚点随球推进，无对方门区约束） |

**FIRA 规则**（docs/00）：
- 门区（对方球门前 50×15）除门将外**停留 >20 周期** → 罚点球
- 门区 **2+ 人**（任意时长）→ 罚点球
- 禁区（80×35）**4 人** → 罚点球

## 2. 修改建议

### 建议 A：对方门区禁入约束（最小改动，推荐先做）

**位置**：`roles.cpp` 的 `run_passive` / `run_midfield` / `run_assist` 进攻分支末尾（或统一在
`motion::position` 调用前加一个 helper）。

**思路**：现有 `in_penalty_area(ctx, x, y)` 只查己方罚球区。新增对称的对方门区检查：
站位点落入**对方门区**（对方球门前 50×15）时，沿 x 推出到门区前缘 5cm。

```cpp
// roles.cpp 或 situation.cpp 新增（参考现有 in_penalty_area 的写法）
// 对方门区禁入：进攻站位不得进入对方门区（50×15），防止 2+ 人聚集被判点球
static void clamp_out_opp_goal_area(const TeamContext &ctx, double &x, double &y) {
    double opp_gx = ctx.opp_goal_x();
    double ad = ctx.attack_dir();
    // 对方门区：x 以对方门线为基准向场内 50cm，y 门宽±7.5
    double lo = (ad > 0) ? opp_gx : opp_gx - 50.0;      // 门区 x 下界（蓝攻+x时对方门在0）
    double hi = (ad > 0) ? opp_gx + 50.0 : opp_gx;      // 上界
    bool in = (x > lo && x < hi && y > 62.5 && y < 117.5);
    if (in) {
        x = (ad > 0) ? lo - 5.0 : hi + 5.0;             // 推到门区前缘外 5cm
        y = clamp(y, 70.0, 110.0);
    }
}
```

**调用点**（3 处，都在各自站位计算完之后、`motion::position` 之前）：
- `run_passive`：人盯人站位 `mx,my` 算完后（现有 in_penalty_area 之后再加一层）
- `run_midfield`：进攻站位点算完后
- `run_assist`：助攻站位点算完后

**例外**：`run_active`（ACTIVE 带球/射门）**不加**——带球压门是进攻必需，
规则只罚"2+ 人"和"停留>20 帧"，单人冲门抢射是正常进攻。

### 建议 B：盯人目标过滤（可选，配合 A）

`run_passive` 人盯人时，若被盯者在**对方门区内**且球不在门区（即对方防守球员缩在门区里），
改为放弃盯人、站门区前缘（免得跟进去）：

```cpp
// run_passive 人盯人分支开头加：
if (in_opp_goal_area(ctx, wm.opp[t].x, wm.opp[t].y) && !ball_in_opp_goal_area(wm)) {
    // 被盯者缩在对方门区里，球也不在门区 → 不追进去，改站门区前缘
    motion::position(wm.home[id], ctx.opp_goal_x() - ctx.attack_dir() * 55.0,
                     clamp(wm.ball.y, 72.5, 107.5));
    return;
}
```

### 建议 C：ACTIVE 停留时限（进阶，可选）

规则是"单人停留>20 周期也罚"。ACTIVE 在对方门区连续停留超 20 帧（0.5s）时应主动撤出
（比如往回带或传球）。这个改动收益小（ACTIVE 通常在推球是移动的），优先级低。

## 3. 验证方法（必须跑）

```bat
:: 改前基线（当前: 门区违规 ~12.9 次/场）
python tools\py\sim_eval.py run baseline --games 50 --seed 1

:: 改后
python tools\py\sim_eval.py run fixed --games 50 --seed 1
python tools\py\sim_eval.py compare sim_eval_baseline.json sim_eval_fixed.json

:: 预期：「门区违规/场」从 ~12.9 显著下降（目标 <3 次/场）
:: 同时盯「我们场均」不能掉（站位外推可能牺牲一点进攻），
:: 若掉 >0.5 球说明外推太狠，可把 5cm 余量加大或只约束 2+ 人时才外推后到场的那个
```

**最终验证**：真实平台跑 3~5 场，看官方 SimuroSot5.log 的 Penalty Kick Blue 次数
（当前场均 1.9 次）是否降到 <0.5 次。

## 4. 注意事项

- 门区坐标以 FIRA 规则为准：**球门前 50×15**（不是罚球区 80×35）；y 范围是门宽 70~110 外扩 7.5
- 只约束非门将 + 非持球进攻者（ACTIVE 推球时不约束，见建议 A 例外）
- 建议先 A 后 B，C 观察数据再定
- 本文档基于 sim_bench 诊断（B 级可靠已验证，见 docs/12），改动后务必跑评估线回归
