## 2. 机理：为什么必然停不准、必然蹭

`motion.cpp:19-63` 的现状：`drive` 在 `de ≥ 5cm` 就饱和（sigmoid 系数 3.0 太陡），
唯一的减速条款 `de<12 && |te|>30`（`:44`）在"正对目标直冲"时**不触发**，
到位判定是 `de < 1.0` 直接 `stop()`（`:23`）。

用真机标定的减速能力算：

```
从 115 cm/s 停下所需距离 = v²/(2a) = 115²/(2·658) = 10.0 cm
而在 de = 1 cm 处才命令停车 → 过冲 10cm 是算术必然（不是调参问题）
要求"1cm 内停住"所允许的速度 = √(2·658·0.01) = 3.6 cm/s
当前 de=1cm 时的命令速度 = 150·(1/(1+e⁻³) − 0.25)·1.0 ≈ 101~115 cm/s → 超标 30 倍
```

→ 输出：冲过目标 → `te` 翻转 ~180° → 落进 `|te|>95` 倒车分支（`:48-54`）反向满速 →
**极限环**。这解释了 2.6× 蹭、3.8× 静止；也解释了为什么代码里要堆 15cm 锚点滞回
（`situation.cpp:114`）、30 帧冷却（`strategy.cpp:107`）、15 帧兜底撤出（`:105`）
——都是在压制症状，代价是**允许最大 15cm 的定位误差**。

## 3. 设计（分期，可独立回退）

### P1（本次）制动包线 + 语义开关 + 输出饱和

```cpp
// motion.hpp
enum TargetMode { TM_STOP = 0, TM_PASS = 1 };   // 停点任务 / 穿越任务
void position(RobotState &r, double tx, double ty, TargetMode mode = TM_STOP);

// motion.cpp
constexpr double kBrakeAccel = 400.0;  // cm/s² 制动设计值（真机 p95=658，取下界留余量）
constexpr double kStopEps    = 1.5;    // cm 死区（≥ 单帧位移量级，吸收离散量化）
constexpr double kMaxWheel   = 140.0;  // 轮速命令饱和（现无夹取，倒车分支可到 -137）

double v_allow = (mode == TM_STOP)
               ? std::sqrt(2.0 * kBrakeAccel * std::max(0.0, de - kStopEps))
               : v_cap;                       // TM_PASS 保持旧行为（只加限幅）
double drive  = std::min(drive_old, v_allow);
if (mode == TM_STOP && de < kStopEps && std::fabs(te) < 40.0) { stop(r); return; }
r.vl = clamp(r.vl, -kMaxWheel, kMaxWheel); r.vr = clamp(r.vr, -kMaxWheel, kMaxWheel);
```

- 删除被包线取代的 `de<12 && |te|>30` 条款（避免两套减速互相打架）。
- 调用点：追球（`move_avoiding` / `chase_ball`）用 `TM_PASS`；锚点/站位/推球点/门将站位用 `TM_STOP`（默认值已是 STOP，改动面最小）。
- 依据：制动包线就是双积分器 |u|≤a 时间最优控制的**切换曲线**（`v=√(2as)`），
  所以它**不牺牲到达时间**（同样的制动段，只是提前 10cm 开始），只消除过冲。

### P2（本方案后半）到点定向 —— 射门真正需要的能力

`motion::position()` 只控制位置，不控制朝向；射门链只能靠"两段式"(先到球后 20cm 再推穿)
+ `|te_ball|<40°` 判据凑，朝向没对准时在两个目标点之间来回切。新增：

```cpp
// 到 (tx,ty) 且机头朝 desired_rot（射门/推球准备）
void position_aligned(RobotState &r, double tx, double ty, double desired_rot);
```

实现：速度仍受 P1 包线约束；朝向误差大时按 `drive *= max(0, cos(te_head))` 削速度
（边走边转，不进入 85~95° 死区），末端 `de<kStopEps` 时若 `|te_head|>tol` 则原地微调到位。
目标：到达时 `|te_head| ≤ 8°`，让下一帧的推球方向就是瞄准线（治"带球射门系统性偏下"）。

### P3（可选，不在本次）路径拐点限速

`follow_route` 目前逐段 `position()`，拐点必进 85~95° 自转死区。按剩余路径长度做
TOPP-lite 限速（`v ≤ min(√(2a·s_剩余), √(a/κ))`）。等 P1/P2 数据出来再评估。

## 4. 验收标准（先写下来，再验；不改标准）

**离线（`offline_test` 新增 4 组）**
1. 包线性质：`de` 从 0.5 扫到 60cm，命令速度恒满足 `≤ √(2·kBrakeAccel·de) + ε`；
2. 物理积分收敛：用真机标定常数（a=658 减速、jump 门限 6cm/帧）积分 200 帧，
   断言"首次进入 ±2cm 后不再离开"，最大过冲 ≤3cm；
3. `position_aligned`：到达 5cm 内时 `|angle_diff(rot, desired_rot)| ≤ 8°`；
4. 饱和：任何输入下 `|vl|,|vr| ≤ kMaxWheel`。

**sim A/B**（`sim_bench` 50 场 × seed 1/2，`--strength 2.0`，与基线同口径）
- 必须不劣化：净胜球（基线 seed1 3.7:4.1 / seed2 3.5:4.0，±0.5 噪声内持平）
- 必须改善（≥1 项显著）：均速、静止帧占比、低速翻转率、射门数、门区滞留帧
- `sim_bench` 新增 `--traj out.csv`：导出逐帧轨迹，让 `motion_calib.py` 用**同一把尺子**量 sim 与真机

**真机**：跑 1 场镜内战 → rlg → CSV → `motion_calib.py`，对比 `traj_before.csv`：
静止帧占比 13.4%↓、低速翻转率 2.3↓。**注意：sim 持平不等于真机不差（docs/03 09-09 教训），真机数据才是终判。**

## 7. 顺手优化：route.cpp 五项 + 属型测试抓到的一个真 bug（2026-09-11，详见 docs/06 第 46 轮）

| # | 问题 | 处理 | 结果 |
|---|---|---|---|
| ① | `plan_route` 与 `plan_route_sub` 重复做直线检查 | 删 `plan_route_sub` 那次（**死代码**：子集 ⊂ 全集，全集被挡 ⇒ 子集必被挡），前置条件写进注释 | 省 5 次点到线段计算/次规划 |
| ② | `add_vertex` O(V) 去重 → 全程 O(V²) | **算法不动**（V≤62、≈1900 次比较，相对 `edge_ok` 的 ≈9500 次距离计算可忽略）；容量守卫前置防 `nv` 越界递增；注释写明"不能只跟本批次比"与"V 上到几百再改哈希" | 可读性/健壮性；不做无效优化 |
| ③ | 3r 补算 = 整轮重跑（最坏 2×） | 改**违例驱动**：只把"真被撞到且不在图里"的圆补进图重算（记录 `sub_idx` 判断是否已在图里） | 图更小、更准；轮数上限 2 |
| ④ | `test_route_avoid` 长度界 (100,200] 太松 | 收紧到 **(100,110)**（真最优≈102）+ 新增"侵入膨胀圈 ≤ margin(0.5)"断言 | 退化会被察觉 |
| ⑤ | `margin` 与 inflate 的关系没写下来 | `route.hpp` 写明契约：判定半径 = r − margin ⇒ 路径允许侵入膨胀圈最多 margin ⇒ 须满足 `inflate ≥ 本体 + margin + 净空`；`roles.cpp` 调用点同步提醒 | 防"把 kRouteInflate 调到 7 而真撞" |

**④ 的产物：属性测试抓到 HEAD 就存在的真 bug（已修）**

`test_route_global_safety` 断言"found=true ⟹ 对**全部**圆安全（含被邻域裁剪掉的远圆）"。
200 组固定种子随机场景中 trial 128 失败：

- obs0 距 S→T 线段 20.03 > 2r=17.96 → 被 2r 邻域裁掉；但绕 obs1(r=17.0) 的路径擦过它，
  最近 6.63cm < (r−margin)=8.48 → **距本体外缘只剩 0.63cm**（真会撞的级别）。
- 机制（插桩确认，非推测）：补算把 obs0 加进图后 **图上无解** —— 切线可见图表达不了
  "沿圆弧绕行"（绕单圆时两切点之间的弦必然穿圆）；旧代码于是把"首轮那条会撞的路径"
  当成功返回（found=true）。旧版 3r 补算同样救不回来。
- 修法：补算轮后做**最终全圆校验**，仍不安全 → `found=false`。
  **契约：found=true 必须意味着真安全**；宁可诚实报告不可规划、让调用方按既有约定走直线兜底。
- 残留限制（TODO，本轮不做）：根治需给可见图加**圆弧边**（或换 Theta*/栅格）。
  生产障碍半径统一 r=10，弦近似够用（单圆用例 min_d=9.8 ≥ 9.5），只在半径很大/两圆紧贴时暴露。

**验证**：`offline_test` **27 组全绿**；随机 200 组穿盘 **0**（修前 1，trial 128 现正确报告
不可规划）；最坏配置规划 **16.3 µs/次**（g++ -O2 x64；docs/03 记的 0.3ms 是 MSVC 32 位口径，
工具链不同不可直接比）。sim A/B 与 motion P1 版逐种子比对**有差异但都在噪声内**
（净胜 Δ 均值 -0.05 球）——差异来自上述契约修正；我原以为会逐位一致，是比对才发现预测错了。

## 8. 射门对准率与机会质量（2026-09-11：全量尝试 → sim A/B 全否决并回退）

**先造尺子**：新增 `tools/py/shot_analysis.py`（真机 rlg / sim `--traj` 同一口径）：
射门尝试 / 射正 / 疑似进球 / 射门机会帧 / **对准率（机头−瞄准线）**。

**真机基线（139s，改动前）**：射门 10.4/分钟、**射正率 8%**（对手 14.2/分钟、48%）；
机会帧 14.9%（对手 22.7%）→ 机会不缺；**机头−瞄准线 p50 = 51.6°、≤10° 仅 6%、>40° 占 64%**
→ 瓶颈是"射不正"。1m 处横向偏差 = 距离·tan(夹角)：40° → 92cm（门半宽只 20cm）。

**实现（4 项）**：① `motion::position_aligned(r,tx,ty,rot)` 到点定向（走位+末端原地转正）；
② 射门执行"球后就地转正→夹角≤10° 才推穿"；③ `shoot.cpp` 机会质量（动态射程 70→110、
净开口角、路线拦截、quality、**点球旁路**）；④ 带球推进也套 20° 对准纪律。

**sim A/B 结论（50 场×4 种子，基线 = motion P1 + route 修复）**：

| 变体 | 内容 | 净胜 Δ |
|---|---|---|
| 全量 | 远射档+连续瞄准+对准纪律 | **-1.68** |
| V1 | 只 shoot.cpp（旧 40° 对准） | **-1.0** |
| V3 | 旧射门决策 + 只加对准纪律 | **-1.63** |
| 最终（已实施） | 三项全回退，留点球旁路+字段+能力 | **-0.2 ± 0.16**（无差异） |

**为什么 sim 判不了**：sim 的 carry 要求球在机头 ±40° 前弧内 → 已隐含"机头对着球"，
真机的 51.6° 误差在 sim 里不构成同等惩罚；sim 又是弱脚本门将 → "快推"优于"推准"。
**这是真机现象，必须真机裁决**（docs/03 反复记录的 sim/真机方向相反）。

**保留的资产**：`position_aligned` + 6 组单测；`ShootPlan` 新字段；远射档开关
`kFarShotEnabled`（一个常量）；**点球旁路**（罚球点 92cm > 70cm 常规射程 → 没有它点球
恒不可射，docs/03 的"点球 0/3 第二根因"）；`shot_analysis.py` 指标工具。

**真机验证清单**：跑一场 → 量对准率/射正率对比基线 → 若确认对准是瓶颈，单开一轮只开
对准纪律；若确认该远射，再单开`kFarShotEnabled`；点球旁路可随下次出包直接生效。
