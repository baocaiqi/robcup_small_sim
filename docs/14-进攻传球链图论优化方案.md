## 0. 摘要

当前 `plan_pass`（src/pass.cpp）是**贪心单跳**：每帧把 4 个队友各算一个接应点，用静态打分
`goal_dist + threat×20 + front_threat×12 + pass_dist×0.5` 选最小。两个结构性弱点：

1. **只看一跳**：看不出"这个接应点拿到球后还能不能继续推进"——传给被盯死的死胡同接应点、
   或推进到一半无路可走（docs/03 复盘"带球有进无退"的传球侧原因）。
2. **阻挡是二值**：对手距传球线 <15cm 直接丢弃，≥15.1cm 与 80cm 大空档同权；不看对手速度。

本方案把每帧传球决策建模成**加权有向图上的多跳接力链搜索**：
- 节点 = 球可达的阶段接应点（每个队友 3 档深度候选）+ 抽象"射门终结"；
- 边 = 推球接力可行性（距离 + **车道连续净空** + 禁区纪律硬约束）；
- 价值 = 用 **Bellman-Ford 式价值迭代**解 `V(u)=min[c(u,v)+γV(v)]`，终结价值=0；
- 输出仍只有**第一跳目标点**，`roles.cpp` 三个调用点零改动。

现状恰好是本方案的**特例**（γ=0、深度=0、净空=二值），参数可连续回退，风险可控。

## 2. 平台与工程约束（红线）

1. **无踢球动作**：FIRA 5v5 小型组"传球"= 把球推/带向接应点（pass.hpp 注释、docs/04 §4）。
   真实场上有接力推进（docs/03 复盘"右路 B3/B5 接力到门前"）。本图模型的边 = **推球接力段**，
   谁物理上推（ACTIVE 追推 / 最近队友顺脚）由既有角色机制决定，图只保证"每段路净空 + 每站有人接应"。
2. **禁区纪律是硬约束**（判点球，最高优先）：
   - 机器人**站位节点**不得进对方门区/罚球区（沿用 `clamp_receive_point` / `clamp_out_opp_goal_area` 口径）；
   - **球**可以进对方门区（射门/单人攻门合法）——终结判定只验球道，不验站位；
   - 候选接应点沿用现有全部纪律夹取，不新增放行。
3. **无第三方库、32 位 MSVC**：图节点 ≤13、边检查 ≤13²×5 对手，每帧 <10⁴ 次距离运算，纯 C++ 数组实现。
4. **roles.cpp 是 UTF-16 被 git 判 binary**（§附录）：本方案**不触碰 roles.cpp**，只改 pass.cpp（UTF-8）
   与 offline_test.cpp（UTF-8），规避二进制合并风险。后续若需改 roles 另开提交先修编码。
5. `plan_pass` 保持**纯函数、只读 wm、签名不变**（`roles.cpp` L390/L443/L466 三处调用只读 viable/target_x/y）。

## 3. 图模型（每决策帧现场建图）

### 3.1 节点集 V

- **源节点 s**：球当前位置 (bx,by)（隐含当前持球推进者在其附近）。
- **阶段节点**：对每个可接应队友 i（i≠passer，且非守门员/无威胁者——沿用现有跳过逻辑），
  以其角色站位点（ASSIST→assist_pt / MIDFIELD→mid_pt / PASSIVE→passive_pt，未分配→本体坐标）为基准，
  沿进攻方向生成 3 档深度候选：

  ```
  cand(i, d) = (ax + ad·(OFFSET_BASE + d·DEPTH_STEP), ay)，d ∈ {0,1,2}
  ```
  DEPTH_STEP ≈ 15cm（初值）。每个候选过 `clamp_receive_point`（夹回场内 + 推出对方罚球区/门区前缘）。
- **终结（不进图的虚拟状态）**：从任一节点/源点位置 P，"可射门"则 V(P)=0。
  可射门谓词 `shootable_from(P)`（镜像 plan_shoot 口径）：
  - 球位 P 距对方球门中心 ≤ 70cm（射程，src/shoot.cpp L20）；
  - 球位 P → 门柱开口（选 GK 远侧，aim=106/74，同 shoot.cpp）的**车道净空 ≥ HARD_BLOCK**；
  - P 不在点球/死球豁免场景（沿用 run_active 的调用时序保证——plan_pass 只在射门不 viable 时被调，
    终结判定只是给接力链算价值，不改变射门优先）。

### 3.2 边集 E 与可行性

- 边 u→v 存在当且仅当：
  1. `PASS_MIN_DIST ≤ dist(u,v) ≤ PASS_MAX_DIST`（8~60cm，球能被一段推送到）；
  2. **车道最小净空 ≥ HARD_BLOCK**（15cm，沿用现状安全口径——不引入更冒险的传球）；
  3. v 是阶段节点时 v 已过纪律夹取；v 是球位终结时只验车道；
  4. 边不做方向限制（允许回传/横传作为接力链的一环——这正是链搜索的价值）。

### 3.3 连续风险权（方案 B）

把二值 `route_blocked` 升级为**车道风险函数**（新增，替换打分里的"挡/不挡"信息）：

```
lane_risk(u, v) = Σ_{opp j} g(d_j)
d_j = 对手 j 到线段 uv 的最短距离（复用 point_to_segment_dist）
g(d) = clamp((HARD_BLOCK / max(d, 1e-6))^2, 0, K_RISK_CAP)   // d=15→1.0，d=30→0.25，d=60→0.06
```

- `d < HARD_BLOCK` 的边已被 3.2 硬剔除 → g 只在可行边上给梯度；
- 硬剔除保留（与现状行为口径一致），g 只做**可行边之间的优劣区分**。

### 3.4 边代价与价值函数（方案 A）

```
边代价   c(u,v) = K_LEN·dist(u,v) + K_RISK·lane_risk(u,v) + K_END·endpoint_threat(v)
endpoint_threat(v) 沿用 count_near_opponent(v)（距离加权，贴脸≈1.0）

价值函数 V：终结=0；其余 V(u) = min_{v∈succ(u)} [ c(u,v) + γ·V(v) ]
```

- 图是"接力 DAG"（球只能越推越接近射门区才有价值，回传只在链内作为过渡），
  节点 ≤13 → 直接按边拓扑做 **Bellman-Ford 松弛 3~4 轮**即收敛（等价于 Dijkstra，实现最简单）；
- 决策：`best_v = argmin_v [ c(s,v) + γ·V(v) ]`，`plan.target = best_v`（**仍只输出第一跳**）；
- 每帧重算（无记忆），由 §5 滞回防抖抑制换向抖动。

### 3.5 与现状的关系（保底）

令 γ=0、DEPTH_STEP 退化为只取 d=0、g 退化为二值（<HARD_BLOCK 剔除否则 0）
→ 退化为现有 plan_pass（K_* 映射到现有 20/12/0.5 权重可再校）。**任何调参事故可一键回退**。

## 5. 常量与初值（进 docs/06 调参表）

| 常量 | 初值 | 含义 | 对应现状 |
|------|------|------|---------|
| DEPTH_STEP | 15.0 cm | 接应点深度档距 | OFFSET_BASE=6 单档 → 3 档 |
| HARD_BLOCK | 15.0 cm | 车道硬剔除阈值（保留现状口径） | BLOCK_THRESHOLD |
| K_RISK_CAP | 4.0 | lane_risk 单项封顶 | — |
| K_LEN | 0.5 | 距离代价（对齐现状 pass_dist×0.5 量级） | 0.5 |
| K_RISK | 12.0 | 车道风险权重 | 二值挡路 |
| K_END | 20.0 | 终点威胁权重 | threat×20 |
| γ (GAMMA) | 0.8 | 链折扣：0=只看一跳（现状） | 无 |
| LOOKAHEAD_DEPTH | 2 | 链最大跳数（60×2=120cm，中场起够到射程） | 1 |

初值原则：K_* 与现状权重同量级 → 单跳打分≈现状，链价值只在小数点后改变排序，sim_bench A/B 观察。

## 6. 单元测试（offline_test.cpp 新增）

新增 `test_pass_chain()`（风格沿用现有 printf FAIL/OK，注册进 main）：
1. **死胡同接应被否决（方案 A 核心）**：队友 A 接应点前方被 2 对手封死（A 处无可续边/无射门），
   队友 B 稍远但 B 处可再推一步 → 必须选 B（现状单跳会选 A）。
2. **两跳链优于一跳**：单跳评分 B 略优但 B 是死胡同，A→C 构成净空两跳且更接近射程 → 选 A；
   断言 `chain_len≥2` 且 `hop2_id` 正确。
3. **风险梯度（方案 B 核心）**：两接应点距离相同、终点威胁相同，一者车道净空 16cm（险）、
   一者 50cm（宽）→ 必选宽者（现状二值无法区分，可能随机错选）。
4. **纪律不破**：候选生成后无一落入对方门区/罚球区（与现有 4 组 pass 场景同一断言风格）。
5. **回归保底**：现有 `test_pass()` 4 场景 + `test_pass_threat_weight()` **必须保持全绿**
   （γ 初值下等价性验证——若红说明初值破坏单跳偏好，先调参再继续）。
6. **数值/边界**：全场对手贴脸无可行边 → viable=false（回退现有"不传→带球/撤退"行为）；无 NaN。

## 8. 风险与回退

| 风险 | 缓解 |
|------|------|
| 链目标每帧换 → 机器人换向抖动（丢速度，曾吃大亏） | §5 滞回：与现有锚点滞回同思路——**只在"新最优总代价 < 当前执行目标代价 − COMMIT_MARGIN"时才切换**，COMMIT_MARGIN 初值=当前目标代价的 15%；开关可关（=现状行为） |
| 多档候选让传球变长/冒险 | 硬剔除不变（≤60cm、≥15cm 净空），K_RISK 惩罚擦线；A/B 盯传球成功率 |
| 模型假设与实际物理（球滚/减速）不符 | 链只做排序不做承诺：输出仍是单帧第一跳，每帧重估；DEPTH_STEP/γ 可调 |
| roles.cpp UTF-16 合并风险 | 本方案不碰 roles.cpp（§2.4）；如需触碰先单独提交转 UTF-8 |
| 与 C/B 模块接口理解偏差 | §4 只增字段不改语义；实施前把本文档同步给 A/B/C/D |

6. **阶段点纪律**：clamp_receive_point 只推罚球区（y∈[72.5,107.5]），覆盖不了对方门区
