# 每帧决策流水线（调度流程）

> 平台每周期调用 `RunStrategy(Environment*)` 一次。核心思想：**固定角色 + 滞回状态机 + 分层行为**。

## 时序图

```
SimuroSot5 平台
   │ Environment（双方 5 机器人、球三帧、场地、PlayMode）
   ▼
dll_blue/dll_yellow.cpp  RunStrategy
   │ WorldModel::update(env, ctx)      ← 镜像坐标变换（TeamContext）
   ▼
Strategy::run(wm)
   1. sit_.analyze(wm)                  → we_have_ball（球权）
   2. update_team_state(wm)             → 滞回攻防状态机 + threat_level
   3. sit_.update_stand_points(wm)      → 状态感知站位参考点
   4. ra_.assign(wm)                    → 固定角色 0-4
   5. 按角色执行（switch 5 分支）
        ├─ run_goalie   → 门线站位/扑救（defense::plan_defense）
        ├─ run_active   → 追球/带球/射门（motion::chase_ball + plan_shoot）
        ├─ run_assist   → 接应跑位（pass::plan_pass 接应点）
        ├─ run_midfield → 中场衔接/回防
        └─ run_passive  → 区域防守/人盯人（defense::pick_mark_target）
   │ 各角色写回 vl/vr（差速轮速）
   ▼
平台执行移动
```

## 核心机制

### 1. 滞回攻防状态机（strategy.cpp）
- 持球/失球需**连续 3 帧**才翻转 `TS_ATTACK ↔ TS_DEFENSE`
- 消除球权临界时每帧横跳（角色/阵型抖动根因）
- `state_transition` 事件：丢球→立即收缩，夺球→立即前插，不等下帧

### 2. 威胁分级（threat_from_state）
| 条件 | threat_level |
|------|-------------|
| 我方控球 | 0.1 |
| 球在己方禁区 | 1.0 |
| 球在己方半场 | 0.6（朝门快滚升 0.8） |
| 球在对方半场 | 0.4（朝门快滚升 0.6） |

下游阈值：>0.3 assist/mid 回防；>=0.6 passive 人盯人。球速朝门 >6cm/帧 提前升档 = 全队早回防。

### 3. 固定角色（role_assignment.cpp）
0=GK / 1=ACTIVE / 2=ASSIST / 3=MID / 4=PASSIVE。参考官方 demo「固定角色」思想，自研实现。
收益：不每帧换角色 → 少无效转向（有效速度↑）、宽度/阵型保持。

### 4. 蓝黄镜像（TeamContext）
一套逻辑跑两队：`M(x)` 水平镜像、`field_rot`/`goalie_rot` 朝向翻转、`attack_dir` 进攻方向。**改镜像参数 = 全库最热改动点**。

## 死球流程（非每帧）

```
SetFormerRobots / SetLaterRobots / SetBall（平台按 PlayMode 调用）
   └─ formation.cpp：kickoff_formation / freeball_formation / defense_formation
      └─ put() 写位姿 + formation_set_ball 摆球
```

## 调试建议

- 看单帧决策：断点 `Strategy::run` 第 5 步 switch
- 看状态抖动：打印 `wm.team_state / state_transition / threat_level`
- 看角色行为：各 run_* 函数入口
- 复盘比赛：`python tools/py/rlg_analyzer.py 日志.rlg`
