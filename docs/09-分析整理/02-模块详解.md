## 3. 实现层（src/）

### strategy.cpp — 每帧主调度（队员 A）
`Strategy::run` 流水线：局势分析 → 攻防状态机 → 站位参考点 → 角色分配 → 按角色执行。
- `update_team_state`：**滞回状态机**——持球/失球需连续 3 帧（kStateHysteresisFrames）才翻转 TS_ATTACK/TS_DEFENSE，治"角色/阵型抖动"；`state_transition` 标记切换事件供下游即时响应
- `threat_from_state`：威胁等级 = 状态 + 球位（己方禁区 1.0 / 己方半场 0.6 / 对方半场 0.4），球速朝门 >6cm/帧 时提前升档（0.8/0.6），触发全队早回防

### role_assignment.cpp — 固定角色（队员 A）
`assign`：0=GK 1=ACTIVE 2=ASSIST 3=MID 4=PASSIVE。固定角色 → 不每帧换角色 → 少无效转向、保持宽度/阵型。区域触发由角色行为实现。

### world_model.cpp — 世界模型
`WorldModel::update(Environment, TeamContext)`：平台数据 → 内部结构（含镜像坐标变换）。

### situation.cpp — 局势分析
- `SituationModule::analyze`：球权/半场/禁区判定
- `update_stand_points`：状态感知站位参考点（进攻锚点 vs 防守锚点）

### motion.cpp — 差速轮控制（队员 B）
- `stop`：vl=vr=0
- `angle`：转向目标角
- `position`：移动到目标点（含朝向）
- `chase_ball`：追球（用预测球位 BallState）

### shoot.cpp — 射门决策（队员 B）
`plan_shoot(WorldModel, shooter_id)`：产出 ShootPlan（是否射/射门点/开口选择）。

### pass.cpp — 传球决策（队员 C）
- `route_blocked`：传球线路是否被挡（几何判定）
- `count_near_opponent`：接应点附近对手密度
- `clamp_receive_point`：接应点钳制在安全区
- `plan_pass`：选出最佳接应点（威胁距离加权——最新 commit 特性）

### formation.cpp — 死球摆位（队员 A）
- `M / field_rot / goalie_rot`：蓝黄镜像工具
- `put`：写机器人位姿
- `defense_formation` / `kickoff_formation` / `freeball_formation`：三类摆位
- `formation_former` / `formation_later`：前/后场机器人摆位分发
- `formation_set_ball`：死球摆球
- `estimate_freeball_x/y`：争球位置估计

### defense.cpp — 防守（队员 D）
- `intercept_point`：拦截点计算
- `plan_defense`：防守计划（站位/上抢/收缩）
- `mark_threat`：盯人威胁打分（球距/门距加权）
- `pick_mark_target`：选盯防目标（带当前目标记忆，防抖）

### roles.cpp — 角色行为薄壳（B/C/D 各管一部分）
- `spread_y`：纵向拉开辅助
- `run_goalie`（D）：守门员——门线站位/扑救
- `run_active`（B）：主攻——追球/带球/射门
- `run_passive`（D）：中卫——区域防守/人盯人
- `run_assist`（C）：助攻——接应跑位
- `run_midfield`（C）：中场——衔接/回防

### offline_test.cpp — 离线冒烟测试
不依赖平台的策略测试（300 帧 + 摆位 12 态），CI 验证用。cbm 索引为 parse_partial，以源码为准。
