# 23 路径规划：换成均匀网格 A*（2026-09-12，用户指令）

> 状态：**已实现 + 单测全绿 + 已部署** ｜ 提出：用户 ｜ 影响文件：`src/route.cpp`（内核重写）、
> `include/simuro5/route.hpp`（注释）、`src/offline_test.cpp`（新增 2 组测试 + 1 条耗时红线）

## 一句话

把"在障碍圆之间连切线（可见图）+ Dijkstra"换成"**4cm 网格 + A* + 视线拉直**"：
跑得更远、能绕墙、能贴墙、能绕大圆，路径长度仍贴着理论最优（教科书用例只差 0.9%），
耗时基本不变（同机同场景 18.2µs → 18.4µs）。

## 为什么换（旧可见图的三个先天缺陷）

比喻：旧算法像"只会沿着柱子边缘拉橡皮筋"——场上只有柱子时它很优雅，但**它不知道球场有围墙**，
也不知道两面墙之间的走廊该怎么走。

1. **没有场地边界概念**：可见图只在障碍圆上取切点，路径可以贴着边线甚至出界；
   真机上"贴边 → 撞墙/被判出界"没有模型保护。
2. **表达不了"沿圆弧绕行"**：两个大圆（或重叠圆）封住走廊时，切点之间的**弦必然穿圆**，
   `found=false` → 调用方回退**直线移动** → 机器人直着往人身上撞。
   （旧代码注释里就记着这个属性测试反例。）
3. **随障碍数组合爆炸**：顶点数 ~4·C(n,2)+4n+2，n=5 时 62 个顶点、还要做"邻域裁剪 +
   违例驱动补算"两轮特判才敢用 —— 全靠裁剪才快，裁剪本身又是漏判的来源。

## 算法（`src/route.cpp`，四步）

1. **快速路径**：`S→T` 直线不穿任何圆盘 → 直接返回 2 个 waypoint（绝大多数调用走这里，~1µs）；
2. **均匀网格 A***：格边长 4cm（55×45=2475 格），8 邻域，估价 `f = g + h`，
   `h` 用八方向距离（可采纳 ⇒ 首次弹出终点即网格最优）；开表是**定长二叉堆**，
   所有缓冲区都是函数内 `static` 定长数组（**零分配**，沿用本仓库风格）；
3. **视线拉直**：贪心"能看多远走多远"，把阶梯路径压成 2~4 个 waypoint 的折线
   （执行层 `motion::follow_route` 只认折线，段太多会抖）；
4. **全圆安全校验**（正确性锁）：拉直后每段必须对**全部**圆安全，否则 `found=false`，
   由调用方按既有约定回退直线移动（宁可诚实失败，也不返回会撞的路径）。

### "不可走格"的两条规则

| 规则 | 判据 | 为什么 |
|------|------|--------|
| 圆盘 | 格中心到圆心距离 `< r + 半对角线(2.83cm)` | 只有"**整格**都在圆外"才放行 ⇒ 相邻两格中心的连线（必在这两格的并集内）也一定在圆外 ⇒ 网格路径严格不穿圆 |
| 边线 | 格中心离任一边线 `< 4cm` | 等效把球场围墙当障碍（旧实现完全没有）；起/终点所在格强制放行，避免"贴墙的目标判无解" |

拉直用的判定半径是 `r − margin`（契约允许路径侵入膨胀圈最多 0.5cm），
所以"严格不穿圆"的网格路径拉直后**贴着切线走**，实测单圆绕行离圆心 9.8cm（膨胀圈 10）。

## 证据（同一台机器、同一套固定种子场景）

| 指标 | 旧：可见图+Dijkstra | 新：网格 A* |
|------|--------------------|-------------|
| 200 组随机 5 圆场景「可规划」数 | 169 / 200 | **176 / 200** |
| 其中"返回路径穿盘"数 | 0 | **0** |
| 最坏配置耗时（5 圆全入图，2000 次平均） | 18.2 µs | 18.4 µs |
| 单圆教科书用例长度（解析最优 102.01） | — | **102.95（超 0.9%）** |
| 200 组随机单圆：最坏超出解析最优 | — | **5.0%** |
| 场地边界 | 无模型 | 全部 waypoint 在场内（贴边用例实测最小离边线 6cm） |

"可规划 169 → 176"的含义：**有 7 组场景旧实现直接放弃（回退直线 = 直着撞人），新实现能绕过去**。

### 玩法层 A/B（`sim_eval.py`，50 场同一批开局，seed=1）

| 指标 | 旧可见图 | 新 A* | 判定 |
|------|---------|-------|------|
| 我们 / 对手场均 | 2.6 / 3.9 | 2.3 / 3.6 | ≈持平（净胜球都 **-1.30**） |
| 射门 | 358.1 | **374.0** | ✅ 变好 |
| 争球重置/场 | 110.7 | 109.8 | ✅ 略好 |
| 角区救球触发/场 | 3.6 | **4.3** | ✅ 变好 |
| 门区违规/场 | 0.8 | 0.5 | 略好（在 ±0.5 球波动内） |

⚠️ sim 的绝对值不可当真（脚本对手 ≠ 官方 demo、物理有简化），只看**相对变化**；
真机验证看两件事：① 被对方挡路时的绕行是否更顺；② 有没有"贴边/出界"的怪动作（旧实现无边界模型）。

解析最优解（当尺子用，单圆盘闭式解）：
`len = √(dS²−r²) + √(dT²−r²) + r·Δθ`（Δθ = 两侧切点半径夹角取小，即"贴圆边走"）。

单测位置（`build\Release\offline_test.exe`）：
- `test_route_optimality()`：解析最优对比（教科书 + 200 组随机）+ 贴边障碍在场内；
- `test_route_global_safety()`：沿用（200 组随机穿盘=0、围死回退）+ **新增耗时红线 400µs**；
- `test_route_straight / test_route_avoid / test_route_cluster / test_follow_route`：沿用，
  其中 `test_route_avoid` 仍卡"绕行长度 ∈ (100,110)"（= 不许为了能绕而绕远路）。

## 参数怎么调（改之前先看这张表）

| 常量（`src/route.cpp` 匿名 namespace） | 现值 | 影响 |
|--------------------------------------|------|------|
| `kCell` | 4.0 cm | 调小 → 更贴最优、更慢、窄缝更能过；调大 → 更快、更方 |
| `kWallMargin` | 4.0 cm | 机器人中心离边线的最小距离（贴门线作业若被挡住，先看这里） |
| `kHalfDiag` | 0.707·kCell | 圆的格膨胀量（与 `kCell` 联动，别单独改） |
| `kMaxExpand` | 6000 | A* 扩展上限，超了返回 `found=false`（回退直线） |

⚠️ `ROUTE_MAX_OBSTACLES = 5` 与 `plan_route` 的 `margin=0.5` 契约**没变**：
`inflate ≥ 本体半径 + margin + 期望净空`（现 `kRouteInflate=10`，净空 ∈ [3.5,4.0]cm）。

## 还没做（下一步的钩子）

1. **代价地图**：A* 的真正红利是"可以往格子里加软代价"——例如"对方门区/我方门区加惩罚"
   （把门区纪律从 `roles.cpp` 的**目标点修正**升级成**全局路径代价**），
   "离球近的一侧优先"等。现在只做纯几何最短（故意保持与旧实现同目标，便于 A/B）。
2. **转向代价**：差速轮转弯有代价，A* 可以把"上一格方向"写进状态（`state = (格, 朝向)`），
   现在是纯欧氏距离。
3. **动态障碍**：障碍只按当前帧位置建格；对方机器人移动快时仍可能"刚规划完就被堵"，
   可考虑按速度外推 1~2 帧再做膨胀。
